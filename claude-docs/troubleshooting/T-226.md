# T-226 · `border` shorthand 위에 `borderColor`를 덮으면 리렌더에서 지워진다

- **증상**: 선택된 필터 칩에 `borderColor`를 얹었는데 콘솔에 경고가 떴다.

  > Warning: Removing a style property during rerender (border) when a conflicting property is set (borderColor) can lead to styling bugs. To avoid this, don't mix shorthand and non-shorthand properties for the same value.

  **화면은 멀쩡해 보인다.** 첫 렌더에서는 색이 제대로 붙고, 리렌더가 일어난 뒤에야 테두리 색이
  기본값으로 풀린다. 스크린샷 한 장으로는 절대 안 잡히고, `getComputedStyle`도 리렌더 전에 재면
  정상값을 돌려준다.

- **원인**: 베이스 스타일(`ui.chip`)이 `border: '1px solid var(--line)'`라는 **shorthand**를 쓰는데,
  쓰는 쪽이 `borderColor`라는 **non-shorthand**만 덮었다. React는 인라인 스타일을 diff 해서
  바뀐 속성만 지우고 다시 넣는데, 이 둘이 같은 값을 두고 겹치면 어느 쪽을 남길지 정할 수 없어
  non-shorthand 쪽을 제거한다. CSS 클래스였다면 캐스케이드가 알아서 처리했을 문제라,
  **인라인 스타일 객체를 스프레드로 합치는 구조에서만 생긴다.**

- **해결**: **베이스에서 shorthand를 없앤다.** 호출부마다 `border` 전체를 덮는 것보다 싸고,
  앞으로 그 베이스를 쓰는 모든 곳이 안전해진다.

  ```ts
  // ui.ts
  chip: {
    borderWidth: 1,
    borderStyle: 'solid',
    borderColor: 'var(--line)',   // border: '1px solid var(--line)' 였다
  }
  ```

  실제로 이 레포에는 같은 버그가 **두 곳**에 있었다 — 새로 만든 필터 칩과, 홈 화면의 목적 칩.
  베이스 한 곳을 고치니 둘 다 나았다.

- **재발방지**:
  - **베이스로 쓰이는 스타일 객체에는 shorthand를 두지 않는다** — `border`·`background`·`padding`·`font`·`flex`가
    다 같은 함정이다. 덮어쓸 가능성이 있는 속성일수록 쪼개 둔다.
  - **콘솔을 판정에 넣는다.** 이 버그는 화면·`getComputedStyle`·스크린샷 어느 것으로도 안 잡히고
    콘솔 경고 하나로만 드러났다. 「보기에 멀쩡하다」는 통과 근거가 못 된다.
  - ⚠️ **콘솔 로그가 새것인지부터 확인한다.** 고친 뒤에도 같은 경고가 계속 보여 수정이 안 먹은 줄
    알았는데, **MCP 콘솔 도구의 버퍼에 남은 옛 로그**였다. 페이지에서 `console.clear()`를 불러도
    그 버퍼는 안 비워진다. 판별은 **스택의 라인 번호**로 한다 — 경고가 가리키는 줄과 현재 소스의
    줄이 다르면 옛 로그다. 확실히 하려면 **새 탭에서 다시 연다**(버퍼가 탭 단위라 비어 있다).
    「이상값을 만나면 앱보다 관측 경로를 먼저 의심한다」의 한 사례다.
