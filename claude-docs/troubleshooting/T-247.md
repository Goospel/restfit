# T-247 · 릴리즈 노트에 깨진 한글 — `\uXXXX`로 손수 쓴 글자는 검증할 방법이 없다

- **증상**: `bundle_submit_review`로 `20260903-31`을 제출했는데, 응답에 실려 돌아온
  `releaseNote`에 **깨진 글자 두 개**가 있었다.

  | 의도 | 실제로 나간 것 |
  |---|---|
  | 팔굽혀펴기 | **팔굴혀퐀기** |
  | 안내는 … 휴식에만 **뜨고** | 안내는 … 휴식에만 **뜼고** |

  앱 문구는 멀쩡하고 **릴리즈 노트만** 틀렸다. 심사자가 읽는 문서라, 하필 이번 번들의 주인공
  기능(운동 이름 검색)을 설명하는 문장 한가운데서 단어가 깨졌다.

- **원인**: 한글을 **JSON `\uXXXX` 이스케이프로 직접 써서** 넘겼다. 코드포인트를 손으로
  적는 셈이라 한 글자만 어긋나도 **그럴듯한 다른 한글**이 된다.

  ```
  팔 굴 혀 퐀 기  →  팔 굴 혀 퐀 기   ← 보낸 것
  팔 굽 혀 펴 기  →  팔 굽 혀 펴 기   ← 의도
        ~~~~~       ~~~~~
  ```

  ⚠️ **에러가 안 난다.** 두 값 모두 유효한 한글 코드포인트라 API도 JSON 파서도 통과시킨다.
  「Windows 셸 한글 원칙」의 무성 실패와 같은 계열인데, 이건 셸이 아니라 **내가 직접 만든
  깨짐**이라 인코딩을 고쳐도 안 잡힌다.

  그리고 이 값은 **검수 요청과 같은 호출에서 확정된다** — 보내는 순간 `REVIEWING`이 되고,
  `bundle_set_release_note`는 `CREATED`·`REJECTED`에서만 먹는다. **되돌릴 창이 아예 없다.**
  (`review_cancel`은 답이 아니다 — 한 번 취소한 배포는 영구히 재검수 요청이 불가능하다.)

- **해결**: 이번 건은 **못 고쳤다.** 다음 번들(`20260904-33`) 노트에서 바로잡았다
  ([`20260902-29`의 「흥러요」](../../plan.md)와 같은 처리였다 — 두 번째였다).

  ★ **다음 번에는 「못 고치는 상황」 자체를 안 만든다.** `20260904-33`에서 실제로 쓴 순서다 —
  확정을 **뒤로 미루는 것**이 요점이다.

  1. 노트 본문을 **파일로 먼저 쓴다**(`Write` 도구 · UTF-8). 눈으로 읽히는 형태로 남고,
     고쳐 쓰기도 그 파일에서 한다.
  2. **위험 단어를 기계로 검사한다.** 눈으로 훑는 것으로는 「팔굴혀퐀기」를 못 잡는다 — 그게
     이 함정의 정의다. 맞는 형태(`팔굽혀펴기`·`뜨고`)는 **있어야** 하고 틀린 형태
     (`팔굴혀퐀기`·`뜼고`·`흥러요`)는 **없어야** 한다는 양방향 검사를 돌린다.
     ⚠️ 검사 스크립트에 한글 리터럴을 넣지 말고 **JSON에 담아 UTF-8로 명시 디코딩**한다
     (BOM 없는 `.ps1`은 PS 5.1이 CP949로 읽는다 — 「Windows 셸 원칙」 3번).
  3. **`bundle_set_release_note`로 먼저 박는다.** `CREATED`에서만 되는 이 호출이 곧
     **되돌릴 창**이다 — 틀렸으면 여기서 몇 번이고 다시 쓴다.
  4. **서버본을 되받아 원본과 바이트로 대조한다.** 응답의 `releaseNote`를 파일로 옮겨
     `-ceq`로 비교하면 전송 중에 깨진 글자가 한 자라도 있으면 걸린다.
  5. **`bundle_submit_review`에 `releaseNotes`를 안 넘긴다.** 이 인자는 필수가 아니라
     (`required: ["deploymentId"]`), 생략하면 3번에서 검사를 통과한 값이 그대로 쓰인다 —
     **두 번 타이핑할 일이 없어져서 오타가 들어갈 자리 자체가 사라진다.**

- **재발방지**: **되돌릴 수 없는 값은 보내기 전에 눈으로 본다.** 판별 기준은 「긴가」가 아니라
  **「이 호출이 상태를 확정하는가」**다.

  | 값 | 고칠 수 있나 |
  |---|---|
  | `memo`(`bundle_upload`) | 관리용이라 틀려도 손해가 작다 |
  | `releaseNotes`(`bundle_submit_review`) | **못 고친다** — 같은 호출이 REVIEWING으로 넘긴다 |
  | `releaseNotes`(`bundle_set_release_note`) | **고칠 수 있다** — CREATED·REJECTED에서 몇 번이든 |
  | 커밋 메시지 | 머지 전이면 고칠 수 있다(T-026의 `.commit-msg-tmp` 경유) |

  표의 2·3행이 **같은 값인데 고칠 수 있느냐가 갈린다.** 되돌릴 수 없는 호출을 피할 수 없다고
  단정하기 전에 **같은 일을 하는 다른 호출이 있는지** 본다 — 여기서는 그것이 답이었다.

  커밋 메시지는 이미 파일 경유 규칙이 있다(T-026). **릴리즈 노트도 같은 등급**이라는 것이
  이번에 드러난 것이다 — 오히려 커밋보다 무겁다. 커밋은 다시 쓸 수 있지만 이건 못 쓴다.
