# T-214 · Git Bash `/c/...` 경로를 Node에 넘기면 무성 실패한다

- **증상**: Bash 도구에서 여러 프로젝트의 `package.json` 의존성을 한 번에 훑으려고 아래처럼 돌렸더니, `=== 프로젝트명 ===` 헤더만 찍히고 **의존성이 한 줄도 안 나왔다.** 종료코드는 1인데 에러 메시지는 안 보였다. 파일이 실제로 존재하는데도 "package.json이 없는 프로젝트인가" 로 오인했다.

  ```bash
  # 실패한 형태
  f="/c/Users/kimsa/ClodeProjects/$p/package.json"
  if [ -f "$f" ]; then
    node -e "const j=require('$f'); console.log(Object.keys(j.dependencies))" 2>/dev/null
  fi
  ```

  `[ -f "$f" ]`는 **통과한다**(Bash는 `/c/...`를 이해한다). 그런데 `node`가 같은 경로를 못 읽는다.

- **원인**: `/c/Users/...`는 **Git Bash(MSYS)의 가상 경로**다. Bash 내장 명령은 이해하지만, **Node.js는 Windows 네이티브 프로세스라 `/c/...`를 해석하지 못한다.** `require()`는 `MODULE_NOT_FOUND`를 던지는데, 위 코드에서 `2>/dev/null`이 그 에러를 삼켜 **아무 출력 없이 종료코드만 1**이 됐다. 조건문이 통과했기 때문에 "파일은 있는데 내용이 비었다"처럼 보인다.

  글로벌 CLAUDE.md의 「MSYS path conversion」(`/foo/bar` → `C:/Program Files/Git/foo/bar` 무성 변환)과 **인접하지만 다른 함정**이다. 그쪽은 Bash가 인자를 변환해서 생기고, 이쪽은 변환 없이 그대로 넘어간 MSYS 경로를 네이티브 프로세스가 못 읽어서 생긴다.

- **해결**: 네이티브 exe(node·python 등)에 넘기는 경로는 **Windows 형식(`C:/Users/...`)으로 준다.** 그리고 진단 중에는 `2>/dev/null`로 stderr를 지우지 않는다.

  ```bash
  # 고친 형태 — grep으로 대체해 Node 경로 문제 자체를 회피
  grep -A25 '"dependencies"' "/c/Users/kimsa/ClodeProjects/$p/package.json" | head -30
  ```

  Node를 꼭 써야 하면 `C:/Users/...` 형식으로 넘기거나, 파일을 stdin으로 흘려보낸다.

- **재발방지**:
  1. **Bash 조건문이 통과했다고 네이티브 프로세스도 그 경로를 읽는다고 가정하지 않는다.** `[ -f ]`와 `require()`는 서로 다른 경로 해석기를 쓴다.
  2. **진단 목적의 명령에는 `2>/dev/null`을 붙이지 않는다.** 이 건의 실제 손해는 경로가 틀린 것이 아니라 **에러가 지워져 원인이 가려진 것**이다. 억제는 원인을 안 뒤에 붙인다.
  3. "결과가 비었다"는 관측을 만나면 **데이터가 없는 것인지 도구가 실패한 것인지**를 먼저 가른다. 글로벌 CLAUDE.md 「번들 문자열 검사」·「이상값을 만나면 관측 경로를 먼저 의심한다」와 같은 계열의 실수다.
