# T-237 · 자기 deps를 바꾸는 복구 effect는 무한 루프다

- **증상**: 카메라가 끊기면 다시 여는 복구를 넣었는데, **다시 취득한 스트림도 죽어 있는 경우**
  (iOS 화면 녹화 중에는 실제로 muted 트랙이 돌아온다) 화면이 `getUserMedia`를 **3초에 3951회**
  불렀다. 더 나쁜 것은 **「다시 연결」 버튼이 화면에 0개**였다는 것이다 — 상태가 진동해 버튼이
  붙었다 떨어지기를 반복하니, 사람이 손으로 빠져나갈 유일한 문까지 막혔다.

- **원인**: 판정 effect의 deps가 `[cam, shot]`인데 **그 effect가 부르는 `reconnect()`가 `cam`을
  바꾼다.** 재취득이 성공해도 스트림이 「살아 있지 않다」로 판정되면 effect가 다시 돌고 →
  다시 재취득 → 다시 판정. **자원이 나쁜 상태로 돌아오는 한 종료 조건이 없다.**
  「재시도 횟수 제한」을 안 둔 것이 아니라, **재시도가 자기 자신을 트리거하는 구조**였다.

- **해결**: 자동 복구를 **한 번으로 제한**하는 ref. 살아 있는 자원을 잡으면 리셋한다 —
  `useState`가 아니라 `useRef`인 것이 핵심이다(상태로 두면 그 변경이 또 렌더·effect를 부른다).

  ```ts
  if (!cam?.ok) return;
  if (alive(cam.stream)) return void (autoTried.current = false); // 되살아났다 → 자동 재무장
  if (autoTried.current) return setDown(true);                    // 두 번째부터는 사람에게
  autoTried.current = true;
  reconnect();
  ```

  같은 조건 실측이 **3951회 → 2회**, 「다시 연결」 버튼 **0개 → 1개**가 됐다.

- **재발방지**: **복구 effect를 쓸 때 「이 effect가 바꾸는 상태가 내 deps에 있는가」를 먼저 본다.**
  있으면 그건 재시도가 아니라 루프다. 그리고 **재시도의 종료 조건은 「성공」이 아니라 「시도 횟수」로**
  둔다 — 성공을 조건으로 삼으면 영영 실패하는 환경(다른 앱이 자원을 쥐고 있는 동안)에서 안 끝난다.
  테스트는 「복구가 된다」만 재지 말고 **「복구가 실패해도 유한하다」를 호출 횟수로** 잰다
  (호출 수를 세는 목 하나면 된다 — 이 축을 재는 테스트가 0건이라 리뷰까지 살아 있었다).
