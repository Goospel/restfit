# T-219 · 폰트 목록에 있고 로드도 성공하는데 실재하지 않는다 (Figma MCP)

- **증상**: 휴식 화면 시안을 Figma에 만들었더니 **타이머 「0:56」만 통째로 안 그려졌다.** 같은 스크립트로 만든 나머지 텍스트("휴식", "다음 · 딥 - 트라이셉스 2세트", 버튼)는 전부 정상이었다. `use_figma` 스크립트는 **에러 없이 성공**했고 반환값도 멀쩡했다.

- **원인**: 앱 폰트 스택이 `system-ui, -apple-system`이라 실기기 렌더에 맞춰 `SF Pro / Heavy`를 골랐는데, **이 파일에서 실제로 쓸 수 없는 폰트**였다. 고르는 근거로 삼은 신호 두 개가 모두 거짓이었다.

  - `listAvailableFontsAsync()`가 `SF Pro`를 **44개 스타일과 함께** 반환했다
  - `loadFontAsync({ family: 'SF Pro', style: 'Heavy' })`가 **예외를 던지지 않았다** (재확인용으로 다시 불러도 성공했다)

  노드를 직접 재고 나서야 드러났다.

  ```
  { chars: "0:56", family: "SF Pro", style: "Heavy",
    fontSize: 72, w: 0, h: 15, hasMissingFont: true }
  ```

  폭이 0이다. 스크립트 성공은 「폰트가 있다」가 아니라 「API 호출이 거부되지 않았다」만 뜻했다.

- **해결**: 한글이 들어가는 화면이라 `Noto Sans KR`로 통일했다. CSS `font-weight: 800`은 `Black`으로 근사한다 — Noto Sans KR에는 **SemiBold가 없어서** `600`은 `Medium`으로 내린다. (`IBM Plex Sans KR`에는 SemiBold가 있다. `Pretendard`·`Apple SD Gothic Neo`는 목록에 아예 없다.)

  교체 후 같은 자리에서 `w: 148, hasMissingFont: false`를 확인했다.

- **재발방지**: **폰트를 쓴 텍스트는 만든 뒤 `hasMissingFont === false` 와 `width > 0` 을 반환값에 실어 되돌려 받는다.** 목록에 있다는 것도, 로드가 성공했다는 것도 근거가 아니다.

  [T-218](T-218.md)과 **같은 형태의 함정**이다. 거기서는 `ait build`가 한글 `appName`을 통과시켰고, 여기서는 `loadFontAsync`가 없는 폰트를 통과시켰다. 둘 다 검사기가 값을 실제로 쓰는 지점(URL / 렌더)을 안 본다. **약한 검사기의 통과를 사실로 승격하지 말 것** — 값이 쓰이는 자리에서 직접 재야 한다.
