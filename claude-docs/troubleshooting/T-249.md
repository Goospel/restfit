# T-249 · `fonts.check`는 폴백에도 true다 — 폰트 적용은 「폭」으로 재야 한다

- **증상**: 테마 「잉크」의 제목 글꼴(Hahmlet 명조)이 실기기 전 브라우저 확인에서
  **적용됐는지 판정이 안 됐다.**

  ```js
  document.fonts.check('800 24px Hahmlet')  // → true
  getComputedStyle(h1).fontFamily           // → 'Hahmlet, "Noto Serif KR", ..., serif'
  ```

  두 값 모두 「됐다」로 읽히는데, **스크린샷의 한글은 명조가 아니라 고딕으로 보였다.**
  그래서 「Hahmlet은 한글이 없나 보다」라고 잘못 결론 내릴 뻔했다.

- **원인**: 두 값 **어느 쪽도 실제로 그려지는 글꼴을 말하지 않는다.**

  | 값 | 실제로 말하는 것 |
  |---|---|
  | `getComputedStyle(...).fontFamily` | **내가 쓴 CSS 선언 그대로**다. 폰트가 없어도 그대로 나온다 |
  | `document.fonts.check(font)` | 「이 글꼴로 그리는 데 **필요한 폰트가 다 로드됐나**」다. 매칭되는 face가 아예 없으면 **폴백으로 그리면 되니 true**를 준다 |

  즉 **둘 다 실패를 「통과」로 돌려준다** — 「통과는 증거가 아니다」의 교과서적 사례다.
  양성 대조군이 없어서, 「폴백이 아님」과 「이 폰트임」을 가르지 못했다.

- **해결**: **같은 글자를 두 패밀리로 재서 폭을 비교한다.** 폭이 다르면 그 폰트가 실제로
  그려진 것이다.

  ```js
  const w = (family, text, weight) => {
    const c = document.createElement('canvas').getContext('2d');
    c.font = `${weight} 24px ${family}`;
    return c.measureText(text).width;
  };
  w('Hahmlet', '오늘은 당기는 날', 800);              // 168.82  ← 셋이 다 다르다
  w('serif', '오늘은 당기는 날', 800);                 // 174.14
  w('"Pretendard Variable"', '오늘은 당기는 날', 800); // 155.98
  ```

  보조로 `[...document.fonts].filter(f => f.status === 'loaded')`를 본다 — 실제로 활성화된
  face만 나온다(구독 안 한 서브셋은 `unloaded`로 남으니 **개수를 세지 말고 존재만 본다**).

  ⚠️ 눈으로 보는 것도 이 경우엔 못 미더웠다. Hahmlet의 한글은 **800에서 획 대비가 눌려**
  얼핏 고딕으로 보인다. 같은 문장을 600·700·800과 본문 폰트로 **한 화면에 나란히 그려**
  비교하니 그제야 갈렸다 — 판정이 애매하면 **비교 대상을 옆에 붙여** 그린다.

- **재발방지**: **「불러왔나」와 「그려지나」는 다른 질문이다.** 웹폰트를 확인할 때는
  전자를 묻는 API(`fonts.check`·`fontFamily`)로 후자를 판정하지 않는다.

  같은 계열의 다른 자리: `link` 태그가 빌드 산출물에 있는지(`grep`)는 **요청이 나갔는지도**
  말하지 않는다. 실사용 확인은 산출물이 아니라 **계산된 값·그려진 결과**에서 한다
  (글로벌 「통과는 증거가 아니다」 절 ④).
