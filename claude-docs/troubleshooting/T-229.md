# T-229 · jsdom을 전역으로 켜면 `import.meta.url` 기반 파일 읽기 테스트가 죽는다

- **증상**: 온보딩·설정 화면 테스트를 추가하면서 `vite.config.ts`에 `test: { environment: 'jsdom' }`을
  넣었다. 새 테스트는 잘 도는데, **손대지도 않은** `src/data/shareLinks.test.ts`가 「0 test」로
  수집 단계에서 죽었다.

  ```
  ❯ src/data/shareLinks.test.ts (0 test)
  TypeError: The URL must be of scheme file
   ❯ src/data/shareLinks.test.ts:121:15
      const DIR = fileURLToPath(new URL('../../../docs/sharelinks/', import.meta.url));
  ```

  ⚠️ 「0 test」라 **실패 목록에 테스트 이름이 안 뜬다.** 요약 줄의 파일 수만 보면
  (`Test Files 3 failed`) 새로 넣은 두 파일이 실패한 줄 알고 지나치기 쉽다 — 실제로 처음엔
  전체 테스트 수가 228 → 224로 **줄어든 것**이 유일한 단서였다.

- **원인**: jsdom 환경에서는 모듈의 `import.meta.url`이 `file://…`이 아니라 jsdom이 세운
  문서 origin(`http://localhost/`) 기준의 URL이 된다. `fileURLToPath`는 `file:` 스킴만
  받으므로 그 자리에서 던지고, 모듈 최상위라 파일 전체가 수집조차 안 된다.

  이 레포는 **문서와 코드를 대조하는 테스트**(쉐어링크 `.md`의 링크 목록 ↔ `shareLinks.ts`)가
  있어서 테스트가 실제 파일을 읽는다. DOM이 필요한 파일은 화면 테스트 둘뿐인데, 그 둘 때문에
  나머지 열세 파일의 실행 환경까지 바꾼 것이 화근이다.

- **해결**: 전역 설정을 되돌리고 **필요한 파일에서만** 켠다. `vite.config.ts`는 손대지 않는다.

  ```tsx
  // @vitest-environment jsdom
  import { render } from '@testing-library/react';
  ```

  파일 머리(첫 import보다 위)의 이 주석 한 줄이면 그 파일만 jsdom으로 돈다. 설정 파일에
  `environmentMatchGlobs` 같은 걸 추가할 필요도 없다.

- **재발방지**: **테스트 환경은 전역으로 바꾸지 말고 필요한 파일에만 붙인다.** 「화면 테스트가
  생겼으니 jsdom으로 통일」은 그럴듯하지만, 그 순간 **노드 환경을 전제로 쓴 기존 테스트**
  (파일 읽기·`import.meta.url`·`process`)가 조용히 사정권에 든다.

  그리고 **테스트 설정을 건드린 뒤에는 「새로 넣은 테스트가 통과하는가」가 아니라 「전체 개수가
  줄지 않았는가」를 본다.** 수집 단계에서 죽은 파일은 실패 이름을 안 남겨서, 실패 목록만 훑으면
  안 보인다.
