# T-215 · `.gitignore`의 앵커 없는 디렉터리 패턴이 소스 폴더를 삼킨다

- **증상**: Phase 1에서 `miniapp/src/data/` 아래에 `exercises.json`(647개 운동 데이터) · `exercises.ts`(타입) · `labels.ts` · `exercises.test.ts`를 만들고 `git add -A` 후 커밋했는데, **`git status --short`에 이 네 파일이 아예 안 나왔다.** 테스트 84건은 전부 통과하고 `npm run build`도 깨끗했다 — 파일이 디스크에 있으니 당연하다.

  커밋된 `src/logic/equipment.ts`는 `../data/exercises`를 import한다. **새로 클론하면 그 모듈이 없어서 빌드가 깨진다.** 로컬에서는 영원히 안 보이는 실패다.

- **원인**: `.gitignore`에 SQLite 수집기 설계(이미 폐기된 EC2 안) 시절의 한 줄이 남아 있었다.

  ```
  # SQLite 데이터베이스 (수집 데이터는 EC2에만 둔다)
  data/
  ```

  **`/`로 시작하지 않는 디렉터리 패턴은 저장소의 모든 깊이에서 매치된다.** `data/`는 루트의 `data/`만이 아니라 `miniapp/src/data/`·`a/b/c/data/`까지 전부 무시한다. 루트에 둘 생각으로 적은 패턴이 **나중에 생긴 남의 소스 폴더를 삼킨다.**

  두 가지가 겹쳐 조용해졌다:
  1. `git add -A`는 무시된 파일을 **경고 없이** 건너뛴다.
  2. 프로젝트 방향이 바뀌면서(서버 0대) 그 ignore 줄의 원래 목적은 이미 사라졌는데, 줄은 남았다.

- **해결**: 진단은 `git check-ignore -v <경로>` 한 번이면 끝난다 — 어느 파일 몇 번째 줄이 막았는지 그대로 알려준다.

  ```
  .gitignore:21:data/	miniapp/src/data/exercises.json
  ```

  폐기된 설계의 잔재라 블록째 걷어냈다. 남겨야 했다면 **`/data/`로 앵커를 박는다**(루트만 매치).

- **재발방지**:
  1. **`.gitignore`의 디렉터리 패턴은 루트만 노릴 거면 `/`로 시작한다.** `data/`·`build/`·`out/`·`tmp/` 처럼 흔한 이름일수록 남의 폴더를 삼킬 확률이 높다.
  2. **커밋 후 `git status --short` 출력에서 이번에 만든 파일이 전부 보이는지 눈으로 센다.** 특히 새 디렉터리를 만든 커밋에서. 「테스트 통과」는 이 실패를 절대 못 잡는다 — 파일은 디스크에 있으니까.
  3. **설계를 바꿔 폐기한 항목은 `.gitignore`에서도 같이 걷는다.** 목적을 잃은 ignore 줄은 나중에 엉뚱한 것을 막는 지뢰가 된다.
  4. 글로벌 CLAUDE.md의 「이상값을 만나면 관측 경로를 먼저 의심한다」와 같은 계열이다 — 여기서는 *부재*가 이상값이었고, 관측 경로가 `.gitignore`였다.
