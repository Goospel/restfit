# T-238 · 카메라는 켜졌는데 우리 화면에 안 보인다 — 웹뷰가 프리뷰를 전체화면으로 가져간다

- **증상**: 실기기(아이폰 · 토스 iOS 앱)에서 눈바디 촬영 화면의 카메라를 켜면 ① **네이티브
  전체화면 플레이어**가 뜬다 — 움직임은 보이는데 우리가 그린 버튼도 고스트 오버레이도 없다.
  ② 그걸 닫으면 앱 화면의 인라인 `<video>`는 **정지 프레임 한 장**만 보여준다(버튼·고스트는
  제자리에 있는데 프리뷰만 안 움직인다). **셔터를 누르면 사진은 정상으로 찍힌다.**
  즉 「구도를 맞추라고 만든 고스트 오버레이」가 통째로 무용지물인데, 기능은 겉보기에 동작한다.

- **원인**: `miniapp/apps-in-toss.config.ts`의 `webView`에 **`allowsInlineMediaPlayback`이 없었다.**
  WKWebView는 이 값이 **기본 false**라 `video.play()`가 인라인 재생을 거부하고 네이티브
  전체화면 플레이어로 승격시킨다. 화면 코드의 `<video autoPlay playsInline muted>`는 처음부터
  맞았다 — **막은 것은 웹 코드가 아니라 컨테이너 설정**이었다. `getUserMedia`는 정상으로
  열렸고(권한 선언은 PR #49에서 이미 맞춰 뒀다) 스트림도 살아 있어서 `drawImage` 캡처는
  성공한다. 그래서 **「스트림이 있느냐」를 재는 어떤 신호도 이 버그를 못 잡는다.**

- **해결**: `webView`에 두 줄.

  ```ts
  webView: {
    pullToRefreshEnabled: false,
    allowsInlineMediaPlayback: true,        // 인라인으로 그릴 자리를 연다
    mediaPlaybackRequiresUserAction: false, // 음소거 프리뷰가 제스처 없이 재생을 시작한다
  },
  ```

  두 줄이 한 쌍이다 — 앞엣것만 켜면 자리는 생기지만 재생이 사용자 조작을 기다리다
  **정지 프레임에 머문다**(증상 ②와 구별이 안 된다). 키 이름·값 타입은 프레임워크
  `config.d.ts`가 리터럴로 타이핑하므로 **`tsc`가 실제 계측기다**(오타 키 → `TS2561`,
  문자열 값 → `TS2322`로 실측 확인). `appName`이 `string`이라 검증이 없던
  [T-218](T-218.md)과는 여기서 갈린다 — **「빌드 통과 ≠ 유효성」이 필드마다 다르다.**

- **재발방지**: **프로브의 성공 기준에 「어디에 보이는가」를 넣는다.** PR #49의 카메라 프로브는
  「`getUserMedia`가 열리는가」만 재고 성공으로 판정했고, 그 판정은 이 버그를 통과시켰다 —
  스트림 취득과 **그 스트림이 우리 레이아웃 안에서 움직이는가**는 다른 축이다. 실기기 프로브는
  ⓐ 스트림 취득 ⓑ **인라인 재생**(전체화면으로 안 튀는가) ⓒ 우리 UI(버튼·오버레이)가 프리뷰
  **위에 함께 보이는가**를 각각 확인해야 한다. 그리고 **「캡처는 되는데 프리뷰만 죽었다」는
  비대칭을 감별 신호로 기억한다** — 이 모양이면 스트림이 아니라 **표시 경로**(웹뷰 설정·CSS·
  레이어)를 먼저 본다. 미디어 재생·카메라·전체화면처럼 **네이티브가 가로챌 수 있는 기능은
  웹 코드가 맞아도 컨테이너가 뒤집을 수 있으므로**, 웹에서 안 될 때 `config.d.ts`의 `webView`
  옵션 목록을 한 번 훑는 것이 싸다. jsdom에는 웹뷰가 없어 **어떤 단위 테스트로도 못 잡는다** —
  이 축은 실기기가 유일한 계측기다.
