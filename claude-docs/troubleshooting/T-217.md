# T-217 · autocrlf 레포에서 numstat은 EOL 뒤집힘을 못 본다

- **증상**: `apps-in-toss.config.ts`(CRLF)에 `sed -i`로 한 줄을 치환했다. hookify 룰 `warn-inplace-replace-crlf`가 지시한 대로 `git diff --numstat`으로 확인했고 결과는 **정상이었다.**

  ```
  3	0	.gitignore
  4	1	miniapp/apps-in-toss.config.ts   ← 고친 줄만 잡혔다. 룰이 말한 「보존됨」 신호
  2	1	miniapp/package.json
  ```

  그런데 바이트를 직접 보니 **파일 전체가 LF로 뒤집혀 있었다.**

  ```bash
  grep -qU $'\r' apps-in-toss.config.ts   # 매치 없음 → LF
  ```

- **원인**: 이 레포는 **`core.autocrlf = true`** 다. git은 diff를 만들 때 워킹트리를 인덱스와 같은 형태(LF)로 **정규화한 뒤 비교**한다. 그래서 워킹트리가 CRLF든 LF든 **numstat 숫자가 똑같이 나온다** — 줄끝 차이가 비교 이전에 지워진다.

  즉 hookify 룰이 처방한 검증(*"numstat으로 파일당 변경 줄 수를 본다. 파일 전체가 잡히면 뒤집힌 것"*)은 **autocrlf가 없는 레포에서만 작동한다.** autocrlf가 켜진 레포에서는 뒤집혀도 영원히 초록이다.

  신호가 아예 없었던 건 아니다. `git diff`가 stderr로 한 줄 흘렸다:

  ```
  warning: in the working copy of '...', LF will be replaced by CRLF the next time Git touches it
  ```

  **numstat의 숫자에는 안 담기고, 옆줄 경고로만 나온다.** 숫자만 읽으면 놓친다.

- **해결**: 검증을 **바이트로** 한다. 파일 하나면 한 줄이다.

  ```bash
  grep -qU $'\r' <파일> && echo CRLF || echo LF
  ```

  복구도 한 줄(전 줄이 LF일 때만 — 섞여 있으면 `\r`이 겹친다):

  ```bash
  sed -i 's/$/\r/' <파일>
  # 검산: \r 개수 == 줄 수
  grep -cU $'\r' <파일>; wc -l < <파일>
  ```

  애초에 **단일 파일의 정해진 편집이면 Edit 도구를 쓴다** — 대상 줄만 건드리고 EOL을 보존한다. 이번에도 앞선 세 건은 Edit로 해서 멀쩡했고, `sed -i`로 한 이 한 건만 뒤집혔다.

- **재발방지**:
  1. **`git diff --numstat`은 EOL 검증 수단이 아니다.** `core.autocrlf`가 켜져 있으면 무조건 초록이다. 이 레포는 켜져 있다(`git config --get core.autocrlf` → `true`).
  2. **검증 수단을 처방할 땐 그게 이 레포 설정에서 작동하는지 먼저 본다.** 글로벌 룰은 autocrlf 없는 레포를 가정하고 쓰였고, 여기서는 그 가정이 깨진다.
  3. T-216과 같은 계열이다 — **「계측기가 늘 초록인 것」과 「지킬 게 없는 것」은 구분되지 않는다.** T-216은 기계 시간대가 코드 가정과 같아서, 여기는 git 설정이 diff를 정규화해서. 둘 다 **환경이 검사를 무력화**한 경우다.
  4. 승격 후보: hookify `warn-inplace-replace-crlf` 룰 본문의 numstat 처방에 *"단 `core.autocrlf`가 켜진 레포에서는 바이트로 확인하라"* 를 덧붙인다. 4개 프로젝트 8건이 쌓인 룰인데 **처방이 반쯤 장님인 채로 돌고 있었다.**
