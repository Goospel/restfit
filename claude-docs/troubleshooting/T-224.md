# T-224 · 플로팅 탭바 2차 반려 — safe-area에 「더하기」만 하면 바닥값이 없다

- **증상**: [T-222](T-222.md)의 반려를 반영해 탭바를 좌우 20px·아래 `safe-area + 12px`의 흰 캡슐로
  고쳐 재제출했다. **글자 하나 다르지 않은 같은 사유로 또 반려됐다.**

  > 1. 탭바를 사용하는 경우, 토스 미니앱 브랜딩 가이드에 적합한 플로팅 형태를 사용해야 해요.

  ⚠️ 먼저 의심할 것은 **「수정이 그 번들에 실제로 들어갔는가」**다. 릴리즈 노트에 "수정했다"고
  적혀 있어도 그건 사람이 쓴 문장이라 근거가 못 된다. 대조는 두 시각으로 한다:

  | 근거 | 값 |
  |---|---|
  | 수정 커밋 머지 (`git log --date=format:"%H:%M"`) | 22:23 |
  | 번들 업로드 `regTs` (`bundle_list`) | 22:24:25 |

  1분 22초 차이 — **들어가 있었다.** 그러니 리뷰어는 고친 화면을 보고도 미달로 판정한 것이고,
  문제는 「반영 누락」이 아니라 「형태」다. 이 확인을 건너뛰면 엉뚱한 곳을 고치게 된다.

- **원인**: **`safe-area`에 더하기만 했다.**

  ```ts
  bottom: 'calc(var(--safe-b) + var(--tab-gap))'   // --tab-gap: 12px
  ```

  `env(safe-area-inset-bottom)`은 **환경이 주지 않으면 0**이다(홈 버튼 기기, 웹뷰가 안 넘겨주는
  경우, 브라우저). 그러면 이 식은 그냥 **12px**이 되고, 12px은 사람 눈에 「살짝 들린 바」이지
  「떠 있는 캡슐」이 아니다 — 1차 반려 때와 인상이 거의 같다.

  ⚠️ **크롬에서 확인한 것이 함정을 덮었다.** 개발 중 브라우저도 safe-area가 0이라 우리가 본
  화면이 이미 12px 상태였는데, 「어쨌든 떠 있네」로 넘어갔다. **바닥값 없는 여백은 가장 불리한
  환경에서 재야 한다.**

  좌우도 좁았다. 가이드 그림(`Mobile_Tabbar`)에서 캡슐은 화면 폭의 약 **7.6%** 안쪽에 있는데
  (390px 화면이면 30px) 우리는 20px이었다.

- **해결**: **`max()`로 바닥값을 보장**하고, 수치는 가이드 그림에서 비율로 읽어 냈다.

  ```css
  --tab-lift: max(24px, calc(var(--safe-b) + 8px));  /* safe-area가 0이어도 24px */
  --tab-side: 30px;                                   /* 화면 폭의 약 7.6% */
  ```

  검증은 **safe-area가 0인 환경**(브라우저)에서 잰다 — 거기서 통과하면 어디서나 통과한다.

  | 항목 | 가이드 그림 환산(390px 기준) | 실측 |
  |---|---|---|
  | 캡슐 폭 | 330.6px | **330px** |
  | 좌우 여백 | ~29.7px | **30px** |
  | 높이 | ~55px | **56px** |
  | 밑변에서 띄운 거리 | 홈 인디케이터 위로 넉넉히 | **24px** (safe-area 0에서) |

  ⚠️ **가이드에 수치 스펙은 없다.** 그림 한 장뿐이라 프레임 폭을 화면 폭으로 놓고 **비율**로
  환산해야 한다. 이미지 URL은 [UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide)의
  탭바 섹션에서 얻는다(문서 페이지 자체는 목차만 렌더돼서, `.md` 확장자로 받아야 본문이 나온다).

  덤으로 확인한 것: **SDK에 탭바 컴포넌트는 없다.** `node_modules/@apps-in-toss/`에 `TabBar`류
  export가 하나도 없고, `@toss/tds-mobile`은 아예 설치돼 있지도 않다(README가 낡았다).
  「토스에서 제공하는 형태」란 **그림에 맞춰 직접 구현하라**는 뜻이다.

- **재발방지**: **`env(safe-area-*)`에 기대는 여백은 반드시 `max()`로 바닥값을 준다.** 더하기만
  하면 그 값이 0인 환경에서 여백이 통째로 사라지는데, 개발 중에 보는 브라우저가 정확히 그
  환경이라 **끝까지 안 보인다.**

  그리고 **심사 반려를 고칠 때는 한 번에 하나만 바꾼다.** 이번에 탭 아이콘을 솔리드로 바꾸는
  안도 있었지만 뺐다 — 사유가 「플로팅 형태」라 아이콘과 무관하고, 둘을 같이 바꾸면 3차에서
  또 반려됐을 때 **무엇이 원인인지 못 가른다.**

  ⚠️ **스토어 스크린샷도 같이 낡는다.** 탭바 위치가 바뀌었으니 `assets/screenshots/`의 탭바가
  찍힌 장들은 다시 찍어야 한다([T-222](T-222.md)에서 이미 한 번 겪었다).
