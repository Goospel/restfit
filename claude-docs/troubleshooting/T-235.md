# T-235 · 가짜 타이머는 실패한 테스트 밖으로 새어 나간다

- **증상**: 촬영 화면에 새 테스트 8건을 추가하고 **Red를 확인하려고** 돌렸더니 **24건이 빨간불**이었다.
  새로 쓴 8건 말고도 저장·고스트·DB 수명 등 **손대지도 않은 기존 테스트 16건**이 전부
  `Test timed out in 5000ms`로 떨어졌다. 새 테스트가 뭔가를 전역으로 깨뜨린 것처럼 보인다.

- **원인**: 새 테스트 중 하나가 카운트다운을 재느라 `vi.useFakeTimers()`로 열고 마지막 줄에서
  `vi.useRealTimers()`로 되돌리는 이 파일의 기존 관례를 따랐는데, **그 테스트가 (의도대로) 실패하면
  단언에서 던져 복구 줄에 영영 도달하지 못한다.** 가짜 타이머가 켜진 채로 다음 테스트들이 시작되고,
  `findBy*`·`waitFor`가 기다리는 시간이 아무도 안 밀어 주니 전부 5초 타임아웃으로 죽는다.
  **TDD의 Red 단계에서 반드시 터지는 함정이다** — 통과할 때만 되돌리는 복구는 실패할 때 없는 것과 같다.

- **해결**: 파일 수준 `afterEach(() => vi.useRealTimers())`. 통과하든 실패하든 되돌린다
  (각 테스트 안의 `vi.useRealTimers()`는 그대로 둬도 무해하다 — 이미 실시간이면 no-op).

- **재발방지**: **가짜 타이머의 복구는 테스트 본문이 아니라 `afterEach`가 맡는다.** 진단 신호는
  「빨간불의 **모양**」이다 — 실패가 각기 다른 단언이면 진짜 회귀지만, **여러 파일·여러 테스트가
  똑같이 5000ms 타임아웃**이면 그건 n개의 버그가 아니라 **하나가 흘러넘친 것**이다. 원인은 대개
  테스트 사이에 새는 공유 상태(가짜 타이머·목 호출 기록 T-233·전역 게터 재정의)다.
