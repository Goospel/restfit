# T-248 · 돌연변이가 안 박혔는데 초록 — 치환 실패가 「검사 무력」으로 읽힌다

- **증상**: 새로 만든 밀기/당기기 교대 로직에 돌연변이 4종을 넣어 테스트 판별력을 실측했다.
  하나(「나누기를 통째로 끈다」)만 결과가 이상했다.

  ```
  돌연변이 A — 나누기를 통째로 끈다 (splitForce → null)
         Tests  67 passed (67)      ← ⚠️ 아무것도 안 죽었다
  돌연변이 B — 동점 처리를 뒤집는다
         Tests  4 failed | 63 passed
  ```

  A는 기능을 통째로 끈 것이라 **가장 크게 죽어야 할 돌연변이**인데 만점이었다. 사실은
  치환이 아예 안 들어갔다 — PowerShell `-Command` 안의 인용부가 깨져 파싱 에러가 났고,
  그 에러 메시지는 **한글 콘솔에서 CP949로 깨져 나와** 로그의 노이즈처럼 보였다.

  ⚠️ 대상 문자열에 작은따옴표가 들어 있었다(`includes('push')`). PowerShell 리터럴을
  작은따옴표로 감쌌으니 거기서 문자열이 끊겼다.

- **원인**: 돌연변이 테스트에는 **자기 자신을 검사할 계측기가 없었다.** 스크립트는
  ① 치환하고 ② 테스트를 돌리는데, ①이 실패해도 ②는 멀쩡히 돌아 초록을 준다.
  그리고 **초록이 두 가지 정반대 뜻을 갖는다**:

  | 「통과」가 뜻할 수 있는 것 | 실제 상황 |
  |---|---|
  | 테스트가 이 결함을 **못 잡는다** | 돌연변이가 박혔는데 살아남음 → 검사를 고쳐야 한다 |
  | 돌연변이가 **안 박혔다** | 아무것도 안 바뀜 → 측정 자체가 없었다 |

  구별할 방법이 결과 안에 없다. 이게 글로벌 원칙 「통과는 증거가 아니다」의 **돌연변이
  테스트판**이다 — 판별력을 재려고 만든 도구가 정작 자기 고장은 통과 쪽으로 낸다.

  같은 스크립트에서 백업 복원도 조용히 실패했다(`cp A || cp B`에서 A가 성공해
  B가 안 만들어졌는데, 뒤에서 B로 복원하려 했다). 그래서 **돌연변이 3개가 누적**되어
  뒤 두 개의 숫자도 실은 첫 번째를 재고 있었다.

- **해결**: 치환 결과를 **비교해서 안 바뀌었으면 던진다.** 한 줄이면 된다.

  ```powershell
  $new = $t.Replace($from, $to)
  if ($new -eq $t) { throw 'MUTATION NOT APPLIED' }
  [IO.File]::WriteAllText($p, $new, [Text.UTF8Encoding]::new($false))
  ```

  대상은 **인용부가 없는 지점**으로 고른다. `if (!forces.includes('push') || ...)` 대신
  호출부 한 줄(`const force = splitForce(picked, recent);` → `const force = null;`)을
  겨누니 같은 효과에 따옴표가 없다. 다시 돌리니 **8건이 죽었다** — A가 가장 큰 돌연변이라는
  예상과 맞는다.

  복원은 백업 경로를 **변수 하나로 고정**하고 폴백(`||`)을 두지 않는다 — 폴백은 어느 쪽이
  쓰였는지를 흐려서, 복원할 때 엉뚱한 경로를 보게 만든다.

- **재발방지**: **돌연변이 테스트에는 양성 대조군이 「치환이 박혔다」는 사실 자체다.**
  검사 대상이 아니라 **검사 도구**에 계측기를 단다.

  1. 치환은 **적용 여부를 확인**한다(위 `throw`). 확인 없는 치환은 측정이 아니다.
  2. 돌연변이마다 **원본에서 다시 시작**한다 — 누적되면 두 번째부터 숫자가 거짓이다.
     복원 직후 `grep`으로 원본 표식이 돌아왔는지 본다.
  3. **예상과 다른 방향의 결과는 도구를 먼저 의심한다.** 「기능을 통째로 껐는데 만점」은
     검사가 무력하다는 뜻이기 전에 **껐다는 전제가 틀렸다**는 뜻일 확률이 높다.
  4. 한글 콘솔에서는 PowerShell 파싱 에러가 CP949로 깨져 나와 눈에 안 띈다 — 종료 코드나
     명시적 `throw`로 잡아야지, 화면을 읽어서 잡을 생각을 하면 안 된다.
