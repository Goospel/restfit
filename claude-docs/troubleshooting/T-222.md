# T-222 · 하단 탭이 밑변에 붙어 심사 반려 (플로팅이어야 한다)

- **증상**: 첫 심사 제출(`20260826-7`)이 18분 만에 반려됐다. 사유는 **하나뿐**이었다.

  > 탭바를 사용하는 경우, 토스 미니앱 브랜딩 가이드에 적합한 플로팅 형태를 사용해야 해요.

  기능·광고·쉐어링크는 아무 지적이 없었다. **탭바 모양 하나로 전체가 막힌 것이다.**

  ⚠️ **사유가 담기는 필드가 셋인데, 그중 하나는 비어 있다.**

  | 호출 | 필드 | 값 |
  |---|---|---|
  | `review_get` | `rejectMessages` | **`[]`** ← 여기만 보면 "사유가 안 왔다" |
  | `review_get_feedback` | `comments` | 사유 있음 |
  | `bundle_list` | `reviewReason` | 사유 있음 (번들 목록에 그냥 실려 온다) |

  `bundle_list`가 가장 싸다 — 번들 상태를 확인하다 보면 사유가 **덤으로 딸려 온다.**

- **원인**: 탭바를 **보통의 모바일 앱처럼** 만들었다 — `left/right/bottom: 0`으로 밑변에 꽉 붙이고 `borderTop`으로 윗선을 그은 형태다. 안드로이드·iOS 앱에서는 이게 표준이라 의심조차 하지 않았다.

  그런데 미니앱은 **토스 앱 안에 얹히는 화면**이다. 토스 자체의 하단 탭(홈·혜택·토스페이·증권·전체)이 똑같이 밑변에 붙어 있어서, 형태가 겹치면 사용자가 **지금 토스에 있는지 미니앱에 있는지 헷갈린다.** 가이드가 든 이유가 정확히 그것이다.

  [UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md)의 「3. 탭바」:

  > 자체 UI를 사용하더라도 탭바만큼은 제공된 형태에 맞춰 구현해 주세요.

  ⚠️ **수치 스펙은 문서에 없다.** 가이드가 주는 건 그림 한 장(`Mobile_Tabbar`)뿐이라, 거기서 형태를 읽어 내야 한다 — 흰 캡슐이 화면에서 사방으로 떠 있고 그림자가 깔린 모습이다.

- **해결**: 밑변에서 떼고 완전한 pill로 만들었다.

  ```ts
  left: 20, right: 20,                        // 페이지 좌우 패딩과 같은 값
  bottom: 'calc(var(--safe-b) + var(--tab-gap))',
  height: 'var(--tab-h)',
  borderRadius: 999,                          // 높이 56 → 실제 반경 28 (완전 pill)
  boxShadow: '0 6px 20px rgba(0,0,0,0.12), 0 1px 4px rgba(0,0,0,0.06)',
  // borderTop 제거 — 선이 남으면 여전히 「붙은 바」로 읽힌다
  ```

  띄운 만큼 본문 하단 패딩도 늘려야 콘텐츠가 안 가린다. `--tab-gap`을 CSS 변수로 둬서 `ui.page`의 `padding-bottom`과 **같은 출처**를 보게 했다 — 한쪽만 고치면 조용히 가려진다.

  탭 개수는 **최소 2개, 최대 5개**다(우리는 3개).

- **재발방지**: **미니앱 UI를 「모바일 앱의 상식」으로 그리지 않는다.** 호스트 앱 안에 얹히는 화면이라, 네이티브 앱에서 표준인 패턴이 여기서는 오히려 금지된다. 하단 탭·상단 헤더처럼 **호스트와 자리가 겹치는 요소**는 그리기 전에 가이드를 먼저 연다.

  ⚠️ 이 반려의 비용은 심사 왕복 한 번이었다. 새 번들을 빌드해 다시 올려야 하고, 그 사이 **광고 지면의 23일 무노출 시계는 계속 돈다**(2026-08-26 생성 → 9월 18일경 삭제 예정).

  덤으로: **스토어 스크린샷도 같이 낡는다.** 콘솔에 올린 4장 중 3장에 옛 탭바가 찍혀 있어 전부 다시 찍었다. UI를 고치면 `assets/screenshots/raw/`도 함께 의심한다.
