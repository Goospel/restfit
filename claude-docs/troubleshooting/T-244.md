# T-244 · 아티팩트 시안은 스크롤로 못 본다 — 표면 셋이 각자 다른 얼굴로 막는다

- **증상**: 「동작 보기」 시안(3×3 비교표)의 **아래쪽 구간**을 스크린샷으로 확인하려는데 셋 다 막혔다.
  ① `claude-in-chrome` 확장: 휠·`Page_Down`·`End`를 아무리 보내도 스크린샷이 **계속 첫 화면**이다 —
  에러는 없고 스크롤만 안 먹는다. ② 내부 Browser 패널에 `file://`로 시안 HTML을 주면
  JS 실행과 스크린샷이 **「No site is open」**으로 거절된다(페이지는 눈에 보이는데도).
  ③ 내부 패널의 http 탭은 JS도 수치도 멀쩡히 나오는데, 스크롤한 뒤 찍은 스크린샷이 **전부 검다.**
  `chrome-devtools` MCP는 「browser already running」으로 아예 못 띄웠다.

- **원인**: 셋이 서로 다른 이유다 — 그래서 하나를 고쳐도 다음에서 또 막힌다.
  ① 아티팩트 본문은 **cross-origin iframe** 안에 있어서, 확장의 CDP 입력이 iframe이 아니라
  **바깥 문서**에 떨어진다(바깥은 스크롤할 것이 없으니 아무 일도 안 일어난다).
  ② 패널의 `file://` 렌더는 **정적 스냅샷(data:)** 모드라 살아 있는 페이지가 아니다.
  ③ 패널 탭은 **첫 뷰포트 페인트만** 캡처한다 — 스크롤로 내려간 영역은 합성이 안 된 채 찍힌다
  (글로벌 「브라우저 확인」 함정 ①의 변종: 화면에 없는 것은 안 그려진다).

- **해결**: **스크롤을 포기하고 페이지를 끌어올렸다.**
  gitignored `.claude/launch.json`에 `node -e` 한 줄짜리 정적 서버(포트 5311)를 넣어
  `preview_start`로 띄우고, 보고 싶은 구간마다
  `document.body.style.transform = 'translateY(-Npx)'`로 그 구간을 **첫 뷰포트로 옮긴 뒤** 찍었다.
  끝나면 transform 리셋 · `preview_stop` · `launch.json` 원복.
  판정 수치(`getBoundingClientRect`·`scrollWidth`·`animationName`)는 **스크린샷보다 먼저**
  `javascript_tool`로 뽑았다 — 그림이 안 나와도 판정은 끝나 있게.

- **재발방지**: 아티팩트의 **첫 화면 아래**를 봐야 하는 순간부터 이 경로로 시작한다(확장 →
  패널 → 정적 서버 순으로 헤매지 않는다). 확장 탭에서 스크롤을 반복 시도하지 않는다 —
  글로벌 「브라우저 확인」 절의 **「1회 갈아타기 → 안 되면 수치로 마감」** 규칙이 그대로 적용된다.
  그림 없이 끝낼 땐 PR body에 수치를 적고 「스크린샷 없음」을 명시한다.
