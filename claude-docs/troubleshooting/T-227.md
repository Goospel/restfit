# T-227 · iCloud 메모 본문은 DOM에 없다 (canvas 렌더링)

- **증상**: 아이폰에서 모은 쉐어링크를 크롬의 iCloud 메모 탭에서 읽으려 했는데 **본문만 안 잡혔다.**
  스크린샷에는 상품명과 링크가 멀쩡히 보이는데, 같은 순간 `innerText`는 435자짜리 사이드바
  목록만 돌려주고 `toss.im/_m/` 매치는 **0건**이었다. `textContent`(17만 자)로 바꿔도 0건,
  `querySelectorAll('a')`로 앵커를 찾아도 0건.

  중첩 `iframe`을 의심해 `window.frames`를 재귀로 훑어도 프레임은 둘뿐이고 본문은 어디에도 없었다.

- **원인**: **두 가지가 겹쳐 있었다.**

  1. **탭이 백그라운드라 앱이 「로드 중…」에서 멈춰 있었다.** 20초를 기다려도 그대로였다.
     `document.visibilityState`를 `'visible'`로 덮어써도 소용없었고, **스크린샷 1회로 페인트를
     강제하자 그제서야 렌더링이 끝났다**(글로벌 CLAUDE.md 「함정 ①」).
  2. 로드가 끝난 뒤에도 본문이 안 잡힌 진짜 이유는 **편집기가 `<canvas>`로 그려지기 때문**이다.
     `.editor-container` 안에 canvas가 7개 있었다. 텍스트가 DOM 노드로 존재하지 않으니
     `innerText`·`textContent`·앵커 수집이 전부 0인 것이 당연하다 — **읽기 도구를 아무리 바꿔도
     안 나온다.**

  덤으로 확장의 안전 필터가 `innerHTML` 반환을 `[BLOCKED: Cookie/query string data]`로 막아서
  DOM을 눈으로 훑는 길도 닫혀 있었다.

- **해결**: **앱 자신의 복사 기능을 쓰고, 시스템 클립보드를 읽는다.** canvas 편집기라도 선택·복사는
  정상 동작한다.

  ```
  computer: 본문 영역 클릭 → key "ctrl+a" → key "ctrl+c"
  PowerShell: Get-Clipboard -Raw
  ```

  3372자가 **오탈자 없이** 그대로 나왔다. OCR로 링크 문자열(`jnf2rJC3`·`dFbLG9K`)을 읽는 것과 달리
  판독 오류가 원천적으로 없다 — 링크 한 글자가 틀리면 404가 되고 수익이 0이 되는 자리라 이 차이가 크다.

- **재발방지**:
  - **canvas 앱에서 텍스트를 얻는 표준 경로는 「그 앱의 복사 기능 + 클립보드」다.** DOM 파고들기는
    프레임을 한 겹 더 열어 보는 것으로 끝내고, canvas가 보이면 즉시 갈아탄다.
  - 클립보드는 Claude Code와 브라우저가 **같은 PC에 있을 때만** 통한다. 원격·다른 기기의 크롬이면 못 쓴다.
  - ⚠️ **사용자의 클립보드를 덮어쓴다.** 복사해 두신 게 있으면 날아가므로 미리 알린다.
  - 「스크린샷에는 보이는데 코드로는 안 잡힌다」는 신호를 만나면 **관측 경로부터 의심한다** —
    이번엔 그 신호가 백그라운드 스로틀(①)과 canvas(②) 둘 다를 가리키고 있었다.
