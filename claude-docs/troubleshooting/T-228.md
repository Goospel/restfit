# T-228 · 쉐어링크에서 뒤로 가기를 누르면 앱으로 안 돌아온다

- **증상**: 기구 추천에서 상품을 누르면 토스쇼핑이 열린다(여기까지는 정상). 그런데 **뒤로 가기를
  누르면 미니앱으로 안 오고 토스쇼핑 안에서 움직인다.** 사용자는 앱으로 돌아갈 길을 잃는다.

  ⚠️ **plan.md에 「우리 앱에는 해당하지 않는다」고 적혀 있어 한 번 걸러졌다.** 2026-08-26 실기기
  검증이 통과했다고 기록돼 있었기 때문이다. 그런데 **그 검증은 다른 것을 봤다**:

  | | 본 것 | 결과 |
  |---|---|---|
  | 8/26 검증 | 돌아왔을 때 **앱 상태가 유지되는가**(재시작 여부) | ✅ 기구 탭 그대로 |
  | 8/27 제보 | **뒤로 가기가 어디로 가는가** | ❌ 토스쇼핑에 머문다 |

  둘 다 「복귀」라는 한 단어로 적혀 있어 같은 것을 검증한 줄 알았다.

- **원인**: **플랫폼에 방법이 없다.** 셋을 실측·공식 답변으로 확인했다.

  1. **SDK에 인앱 웹뷰가 없다.** `Device.openURL`의 시그니처가 `(url: string) => Promise<void>`
     — URL 문자열 하나만 받는다. 인앱으로 열라는 옵션도, 복귀 경로를 넘길 인자도 **애초에 없다.**
     `@apps-in-toss/web-framework@3.1.1`의 export 전체에서 웹뷰를 여는 API는 `openPDFViewer`
     하나뿐이고 PDF 전용이다. `Share.createLink`는 `path`가 `intoss://`여야 해서 **우리 앱으로
     오는** 링크를 만드는 반대 방향 도구다.
  2. **토스 공식 답변**(2026-06-17): *"토스 내 다른 서비스로 이동하는 별도의 SDK / API는
     제공해드리고 있지 않습니다"* — [topic/4102](https://techchat-apps-in-toss.toss.im/t/topic/4102)
  3. **구조상 그렇다.** 토스쇼핑이 자기 네비게이션 스택으로 뜨는데 미니앱은 그 스택에 없다.
     뒤로 가기는 토스쇼핑 안에서만 움직인다.

- **해결**: **고치지 않는다 — 안내로 덮는다.** 상품 목록 **위**에 `RETURN_NOTICE` 한 줄을 뒀다
  (누른 뒤에 읽히면 늦어서 목록 아래가 아니라 위다):

  ```
  상품을 열면 뒤로 가기로는 못 돌아와요. 토스 홈에서 다시 열어주세요.
  ```

  경고가 아니라 **길 안내**로 보이게 했다 — 빨간색·아이콘을 붙이면 「위험한 링크」로 읽혀
  누르기를 망설이게 된다. 배경은 `--bg-sub`가 아니라 **`--bg`(흰색)**: 이 안내가 앉는 카드가
  이미 `--bg-sub`라 같은 색이면 경계가 사라진다. 대비 **4.62:1**로 12px AA(4.5:1) 통과,
  모바일 375px에서 **2줄 52px**(55자짜리 첫 문안은 3줄 70px이라 줄였다).

- **재발방지**:
  - ⛔ **`Device.openURL`을 인앱으로 여는 방법을 다시 찾지 않는다.** 위 셋이 근거다. 찾는 데
    시간을 쓰는 대신, 아래 「고쳐졌는지 보는 법」만 주기적으로 확인한다.
  - ⚠️ **「복귀가 된다/안 된다」를 한 단어로 적지 않는다.** 이 함정이 한 번 걸러진 이유가 그것이다.
    **무엇을 눌러서 무엇이 일어났는지**를 적는다 — 「뒤로 가기 → 토스쇼핑에 머문다」처럼.
  - 📌 **고쳐졌는지 보는 법**: 토스가 **내부 개선 중**이라고 답했다(일정 미정, 2026-08-18 기준).
    고쳐지면 `RETURN_NOTICE`와 쓰는 자리를 지운다. 확인은
    [topic/4525](https://techchat-apps-in-toss.toss.im/t/topic/4525) ·
    [toss-im/4625](https://techchat-apps-in-toss.toss.im/t/toss-im/4625)
  - ⚠️ **토스가 한때 「쉐어링크를 제거하라」고 권고했다**(2026-08-05, 유저 경험·신고 우려).
    다만 우리는 링크가 든 채로 **검수를 세 번 통과했다**(8/26 승인 · 8/27 제출) — 심사 차단
    사유는 아니고 권고다. **신고가 쌓이거나 반려 사유로 나오면 그때 다시 판단한다.**
  - iOS에는 별개 사례도 있다 — 외부 페이지를 연 뒤 **좌측 스와이프로 미니앱까지 종료**된다
    ([ios/4586](https://techchat-apps-in-toss.toss.im/t/ios/4586), 공식 답변 없음).
    `Screen.setIosSwipeBack(false)`는 빠져나올 방법까지 막아 부작용이 크다.
