# 콘솔 등록용 이미지

앱인토스 콘솔 「앱 정보」에 올리는 스크린샷·썸네일. **`store/`는 산출물이고 직접 편집하지 않는다** —
[`scripts/render-screenshots.ps1`](../../scripts/render-screenshots.ps1)이 `raw/`를 재료로 다시 만든다.

```
raw/    앱 화면 원본 (390x844 dPR2 = 780x1688)   ← 손으로 캡처
store/  콘솔에 올리는 결과물                      ← 스크립트가 생성
```

## 규격 — 1px이라도 다르면 업로드가 거부된다

| 용도 | `imageType` + `orientation` | 크기 |
|---|---|---|
| 세로 스크린샷 | `PREVIEW` + `VERTICAL` | **636 x 1048** |
| 가로 썸네일 | `THUMBNAIL` + `HORIZONTAL` | **1932 x 828** |

⚠️ 리사이징·크롭·포맷 변환이 적용되지 않으므로 **규격 해상도 원본**을 올린다.
⚠️ `store/`의 썸네일을 비우면 AI 자동 검수에서 썸네일 항목이 통째로 빠진다.

## raw 다시 찍기

dev 서버(`npm run dev`, `localhost:5310`)를 띄우고 **390x844 dPR2**로 캡처한다.
localStorage에 상태를 심어야 화면이 비지 않는다 — 기구·목적·기록이 없으면 초라하게 나온다.

손으로 찍을 필요는 없다. `chrome-devtools` MCP로 자동화된다 — `emulate`(`390x844x2,mobile,touch`)를
**`navigate_page` 앞에** 걸고, `evaluate_script`로 `restfit.owned`·`restfit.goal`·`restfit.history`를
심은 뒤 `location.reload()`, 탭 전환은 `document.querySelectorAll('nav button')[i].click()`,
저장은 `take_screenshot`의 `filePath`로 바로 `raw/`에 떨군다.

⚠️ **`03`은 스크롤 0에서 찍는다**(2026-08-30 개정 — 옛 「끝까지 내려 찍기」 폐기). 쉐어링크
상품 버튼이 붙어 페이지가 1182px로 길어져, 문구의 근거인 **덤벨 +96개(카드 상단 239px)와
대가성 문구(1042~1078px)가 한 프레임(844px)에 물리적으로 안 들어간다**(실측 2026-08-30).
옛 규칙의 걱정은 「문구가 반쯤 걸친 모습」이었지 프레임 밖이 아니다 — 스크롤 0이면 문구는
프레임 밖이고 하단은 카드가 자연스럽게 잘려 「더 있음」으로 읽힌다. **반쯤 걸친 텍스트가
없는지만 눈으로 확인**하고 찍는다.

| 파일 | 화면 | 심을 상태 |
|---|---|---|
| `01-home.png` | 오늘의 루틴 | 덤벨 보유 + 기록 3건 — **직전 기록이 하체**여야 오늘이 상체(덤벨 종목)로 뜨고, **기록에 오늘 날짜가 없어야** 「운동 시작」이 뜬다 |
| `02-rest.png` | 휴식 타이머 | 위와 같고, 운동 시작 → 세트 완료 1회 |
| `03-shop.png` | 기구 추천 | **맨몸**(`owned: []`) — 덤벨이 +96개로 떠야 한다 |
| `04-history.png` | 기록 | 덤벨 보유 + 기록 3건 + **눈바디 2장**(운동일과 겹치게 — 파랑·초록 쌍 마커와 비교 로우가 찍힌다) |

⚠️ **`04`의 눈바디는 IndexedDB에 심는다** — `restfit-photos` DB의 `photos` 스토어,
`{ date, blob, capturedAt, width, height }` **다섯 필드 전부** 있어야 한다(`isPhoto` 검증이
`width`/`height`까지 봐서 하나라도 빠지면 소리 없이 걸러진다). blob은 canvas `toBlob`으로 만들면 된다.

⚠️ **dev 서버에는 「온보딩 다시 보기」 개발 버튼이 뜬다**(프로덕션 번들에는 없음) — `04`를 찍기 전에
DOM에서 지운다. 단 **사진 비동기 로드가 끝난 뒤에** 지워야 한다(먼저 지우면 리렌더로 되살아난다).

⚠️ `03`만 맨몸으로 찍는다. 덤벨을 가진 상태로 찍으면 덤벨이 추천에서 빠져
**이 화면의 핵심인 「+96개(2.7배)」가 안 보인다.**

⚠️ 세트 입력 화면은 쓰지 않는다. 운동 중에는 하단 탭이 감춰지고 콘텐츠도 적어
캔버스 절반이 빈다 — 큰 타이머가 세로를 채우는 휴식 화면이 낫다.

## 문구

세로 4장의 문구는 스크립트의 `$SHOTS`에, 썸네일 문구는 같은 파일 아래쪽 HTML에 있다.

⚠️ 썸네일은 **기능이 아니라 태도로 연다.** 「루틴을 대신 짜준다」는 흔한 약속이라
구미를 당기지 못한다(2026-08-26 사용자 지적). 앱 이름이 던진 질문에 홈 화면이
*"네, 어렵습니다"* 로 답하는 톤을 그대로 가져왔다.
