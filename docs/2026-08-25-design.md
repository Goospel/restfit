# 토스쇼핑 가격 이력 검증 서비스 — 설계

작성 2026-08-25 · 상태: 승인됨 · 아이템 선정 경위와 접은 안들은 [ideas.md](ideas.md)

## 1. 무엇을 만드는가

토스쇼핑 상품의 **가격 이력을 매일 쌓아, 지금의 할인이 진짜인지 판정**해주는 웹사이트.

```
"할인율 40%라는데, 이 상품 지난 60일 평균가가 오늘 가격보다 쌌습니다."
```

**수익**: 토스쇼핑 쉐어링크 어필리에이트 10%. 상품 페이지의 "토스쇼핑에서 보기" 버튼이 쉐어링크다.

### 왜 이게 되는가 — 구조적 해자

**커머스 사업자는 자기 셀러의 할인이 가짜라고 표시할 수 없다.** 못 하는 게 아니라 구조적으로 안 하는 것이라 영구적이다. 토스가 이 기능을 만들 일은 없다.

경쟁 지형: 다나와·에누리·특가요정은 전부 **쿠팡 중심**이고, 토스쇼핑 쉐어링크 Open API는 이제 막 열렸다(시범운영). 선점 창이 있다.

**그리고 다나와와 정면으로 붙지 않는다.** 토스쇼핑은 오픈마켓이라 중소 셀러 상품이 많고, **그 상품들은 다나와에 없다.** 다나와가 커버하지 못하는 롱테일이 우리 자리다.

### 시장

토스쇼핑 MAU 약 900만 · GMV 전년 대비 +80% · 셀러 수 2배. 토스 유저는 결제수단이 이미 등록돼 있어 **구매 마찰이 거의 0**이다.

## 2. 확정된 제약

설계를 지배하는 사실들. 근거는 [ideas.md §0](ideas.md).

| 제약 | 설계에 미치는 영향 |
|---|---|
| **키워드 검색 API 없음** | 카탈로그 진입점이 랭킹·특가·카테고리뿐. 내가 긁어 만든 인덱스가 곧 해자 |
| **조회 10,000상품/일** (중복도 차감) | *매일 추적 가능한 상품 수 ≤ 10,000.* 수집기 설계 전체를 규정 |
| **링크 발급 10,000건/일** (기존 링크 재요청은 차감 X) | 링크는 DB에 캐싱해 영구 재사용 |
| 10 rps, 버스트 30 | 순차 호출로 충분. 백오프 필요 |
| **출발지 IP 화이트리스트** | EC2 + Elastic IP 필수. 가정용 유동 IP는 조용히 깨진다 |
| 어트리뷰션 24시간 × 전 카테고리 | 추천 상품을 안 사도 그날 산 것이면 인정 |
| **브랜드·도메인에 "토스" 사용 금지** | 서비스명·도메인에 토스 불가. 검색광고에도 토스 키워드 금지 |
| 대가성 문구 필수 | 쉐어링크가 노출되는 모든 페이지에 고정 표시 |
| 조회 API의 `productUrl`은 추적 안 됨 | 반드시 링크 발급 API의 `shortUrl`을 쓴다 |
| 수수료 10%는 이벤트 요율 | 변동 전제로 설계 (요율을 코드에 하드코딩하지 않는다) |

## 3. 아키텍처

```
┌─ EC2 t4g.small + Elastic IP ────────────────┐
│                                              │
│  Next.js (서버 모드)  ──읽기──▶  SQLite      │
│         ▲                          ▲         │
│         │                          │쓰기     │
│      nginx + certbot          cron (매일)    │
│                                    │         │
└────────────────────────────────────┼─────────┘
                                     │
                          쉐어링크 Open API
```

**왜 정적 export가 아닌가**: 상품 하나당 페이지 하나로 수천 페이지가 나오는 SEO 사이트라, 매일 전체 재빌드는 비현실적이다. t4g.nano(0.5GB)로는 Next.js 빌드 자체가 안 돈다. 서버 모드 + SQLite 읽기가 훨씬 단순하다.

**왜 SQLite인가**: 읽기 위주 단일 노드 워크로드다. RDS·Postgres·Redis는 YAGNI. 파일 하나라 백업도 `cp` 한 번이다.

**인스턴스**: t4g.small(2GB). nano/micro는 Next.js 빌드 시 메모리가 부족하다.
⚠️ 2024-02부터 모든 퍼블릭 IPv4에 시간당 과금(~$3.6/월)이 붙는다. 인스턴스비와 별도다.

## 4. 데이터 모델 (SQLite)

```sql
-- 상품 마스터
CREATE TABLE products (
  taca_item_id   INTEGER PRIMARY KEY,
  display_name   TEXT    NOT NULL,
  thumbnail_url  TEXT,
  slug           TEXT    NOT NULL,      -- URL 슬러그 (상품명 기반)
  category_ids   TEXT,                  -- JSON 배열
  first_seen_on  TEXT    NOT NULL,      -- YYYY-MM-DD (KST)
  last_seen_on   TEXT    NOT NULL,
  is_tracked     INTEGER NOT NULL DEFAULT 1
);

-- 가격 이력: 상품 × 날짜 하루 1행 (재실행 멱등)
CREATE TABLE price_history (
  taca_item_id   INTEGER NOT NULL,
  observed_on    TEXT    NOT NULL,      -- YYYY-MM-DD (KST)
  display_price  INTEGER NOT NULL,
  original_price INTEGER,
  discount_rate  INTEGER,
  is_sold_out    INTEGER NOT NULL,
  review_score   REAL,
  review_count   INTEGER,
  source         TEXT    NOT NULL,      -- best | category | deal | detail
  PRIMARY KEY (taca_item_id, observed_on)
);

-- 하루특가 편성 이력 (endAt은 특가 API에만 있다)
CREATE TABLE deal_slots (
  taca_item_id INTEGER NOT NULL,
  observed_on  TEXT    NOT NULL,
  end_at       TEXT,                    -- ISO 8601 KST
  deal_price   INTEGER NOT NULL,
  PRIMARY KEY (taca_item_id, observed_on)
);

-- 쉐어링크 캐시 (한 번 발급하면 영구 재사용)
CREATE TABLE sharelinks (
  taca_item_id INTEGER PRIMARY KEY,
  short_url    TEXT NOT NULL,
  origin_url   TEXT NOT NULL,
  issued_at    TEXT NOT NULL
);

CREATE TABLE categories (
  category_id  INTEGER PRIMARY KEY,
  parent_id    INTEGER,
  level        INTEGER NOT NULL,
  display_name TEXT    NOT NULL
);

-- 수집 실행 로그 (한도 소진·실패 추적)
CREATE TABLE crawl_runs (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  started_at    TEXT    NOT NULL,
  finished_at   TEXT,
  products_seen INTEGER NOT NULL DEFAULT 0,
  links_issued  INTEGER NOT NULL DEFAULT 0,
  status        TEXT    NOT NULL,       -- ok | quota | error
  note          TEXT
);

CREATE INDEX idx_history_item ON price_history(taca_item_id, observed_on DESC);
CREATE INDEX idx_products_tracked ON products(is_tracked, last_seen_on);
```

`PRIMARY KEY (taca_item_id, observed_on)` 덕에 **같은 날 수집기를 여러 번 돌려도 안전하다**(UPSERT).

## 5. 수집기 (cron, 매일 1회)

### 핵심 통찰 — 목록 조회가 곧 이력이다

베스트·카테고리·특가 **목록 조회 응답에 이미 가격이 들어 있다.** 따라서 랭킹에 계속 드는 상품은 목록을 훑는 것만으로 이력이 쌓이고, **추가 비용이 0이다.**

`상품 상세 조회`(product-detail)는 **랭킹에서 빠진 추적 대상에만** 쓴다. 이게 10,000 한도를 가장 아껴 쓰는 방법이다.

### 실행 순서 (우선순위 = 놓치면 영영 못 보는 순)

| 순서 | 대상 | 이유 |
|---|---|---|
| 1 | **하루특가 전량** | 매일 편성이 바뀐다. 오늘 안 받으면 영영 못 본다. 검증 1순위 대상 |
| 2 | **전체 베스트** | 신규 발견 + 이력 갱신을 동시에 |
| 3 | **카테고리 베스트 순회** | 롱테일 발견. 카테고리별 커서를 저장해 다음 날 이어받는다 |
| 4 | **누락 추적 대상 보충** (`product-detail`) | 1~3에서 안 잡힌 `is_tracked=1` 상품. 남은 한도만큼만 |

한도가 소진되면 그 단계에서 멈추고 `crawl_runs.status='quota'`로 기록한 뒤 다음 날 커서부터 이어간다.

> ⚠️ **단계별 한도 배분은 API 승인 후 실측해서 확정한다.** 카테고리 트리의 크기와 하루특가 편성 규모를 모르는 상태에서 숫자를 박으면 틀린다. 1차 수집을 돌려 실제 규모를 잰 뒤 `config`에 넣는다.

### 추적 대상 은퇴 규칙

추적 상품이 한도(10,000)에 근접하면 **`last_seen_on`이 가장 오래된 것부터 `is_tracked=0`** 으로 내린다. 이력은 지우지 않는다 — 과거 페이지는 그대로 남고 갱신만 멈춘다.

### 실패 처리

- HTTP 429 → `Retry-After` 존중 후 재시도
- 5xx → 지수 백오프 3회, 그래도 실패면 해당 단계 스킵하고 다음 단계로
- `SHARELINK_OPENAPI_ACCESS_DENIED` → **즉시 중단하고 알림.** IP가 바뀌었거나 키가 만료된 것이라 재시도가 무의미하다
- `resultType`을 반드시 확인한다. HTTP 200이어도 `FAIL`일 수 있다

## 6. 판정 로직 — 제품의 핵심

```ts
type Verdict =
  | { kind: 'INSUFFICIENT'; observedDays: number }   // 판정 불가
  | { kind: 'ALL_TIME_LOW' }                         // 역대 최저가
  | { kind: 'NEAR_LOW'; low: number }                // 최저가 수준
  | { kind: 'CHEAPER_BEFORE'; low: number; on: string } // ⚠️ 최근에 더 쌌음

verdict(history: PricePoint[], today: PricePoint): Verdict
inflatedOriginal(history: PricePoint[], today: PricePoint): boolean
```

**규칙**

- 관측일 수 < 14 → `INSUFFICIENT`. 페이지에는 *"N일째 추적 중"* 을 표시한다
- `min90` = 지난 90일 관측치의 최저 `display_price`
- `today < min90` → `ALL_TIME_LOW`
- `today <= min90 × 1.02` → `NEAR_LOW` (2% 이내는 같은 가격으로 본다)
- 그 외 → `CHEAPER_BEFORE` + 최저가와 그 날짜를 함께 보여준다

**`inflatedOriginal`**: `original_price`가 관측 이력에서 실제 `display_price`로 나타난 적이 **한 번도 없으면** 뻥튀기로 본다. "원가 10만원"이라면서 10만원에 판 적이 없는 경우다.

**하루특가 전용 판정**: `deal_slots`에 오늘 편성된 상품인데 `deal_price`가 어제 `display_price`와 같으면 → *"오늘만 이 가격"이라지만 어제도 같은 가격이었습니다.*

**엣지 케이스**

- 품절 기간의 관측치도 이력에 포함한다 (가격 자체는 유효)
- 수집 실패로 생긴 관측 공백은 그냥 그 날이 없는 것으로 처리. 최저가 계산에 영향 없음
- `display_price <= 0` 이거나 `original_price < display_price` 인 비정상 응답은 이력에 넣지 않고 `crawl_runs.note`에 기록

이 두 함수는 **순수 함수라 TDD 대상 1순위**다.

## 7. 페이지

| 경로 | 내용 |
|---|---|
| `/` | 오늘의 **진짜** 특가 — `ALL_TIME_LOW`·`NEAR_LOW` 판정만 노출 |
| `/deals` | 하루특가 전체 + `endAt` 마감 카운트다운 + 판정 뱃지 |
| **`/p/{tacaItemId}-{slug}`** | **상품별 가격 이력 페이지 — SEO 롱테일 창구, 수천 개** |
| `/category/{categoryId}` | 카테고리별 목록 |

`/p/*`가 트래픽의 전부다. 구성: 상품 정보 · **가격 이력 그래프** · 판정 뱃지 · 역대 최저/최고 · "토스쇼핑에서 보기"(쉐어링크) · 대가성 문구.

**SEO**

- 슬러그는 상품명 기반. `tacaItemId`를 앞에 둬 상품명이 바뀌어도 URL이 깨지지 않게 한다
- `sitemap.xml` 자동 생성 (추적 중인 상품 전량)
- 구조화 데이터: `Product` + `AggregateOffer` (JSON-LD)
- 상품명이 곧 검색 키워드다. **"토스쇼핑"을 브랜드로 쓰지 않는다** — 상품명 자체로 색인을 노린다

## 8. 수익 연동

- 링크는 **`/p/*` 페이지가 처음 렌더될 때가 아니라 수집 단계에서 미리 발급**해 `sharelinks`에 저장한다. 런타임에 API를 호출하지 않는다
- 같은 상품은 재요청해도 기존 링크가 돌아오고 한도도 차감되지 않으므로, 캐시가 비었을 때만 발급한다
- 버튼은 `shortUrl`을 쓴다. 조회 API의 `productUrl`은 **추적되지 않는다**
- 대가성 문구를 쉐어링크가 있는 모든 페이지 하단에 고정 표시한다

## 9. 테스트 전략

TDD 대상은 순수 함수다. 나머지(수집기 I/O, 페이지)는 얇게 유지한다.

| 대상 | 검증 |
|---|---|
| `verdict()` | 관측일 부족 / 역대최저 / 2% 경계 / 최근에 더 쌌음 / 공백 있는 이력 |
| `inflatedOriginal()` | 원가가 이력에 있음/없음, 이력 0건 |
| 하루특가 판정 | 어제와 같은 가격 / 실제로 내려간 경우 |
| 한도 배분기 | 한도 소진 시 중단·커서 저장·다음날 이어받기 |
| 응답 정규화 | `resultType: FAIL` / 비정상 가격 / 필드 누락 |

Vitest. 기존 프로젝트 관행과 동일.

## 10. 60일 부트스트랩

데이터가 없는 동안에도 사이트는 돌아야 한다.

- **첫날부터 가능**: 하루특가 목록 + `endAt` 카운트다운 + `discountRate` 순위
- **14일부터**: `verdict()` 판정 시작
- **60일부터**: 90일 창이 의미 있게 차서 판정 신뢰도가 올라감

> **SEO는 어차피 3~6개월 걸린다.** 색인이 붙을 즈음엔 데이터가 이미 쌓여 있으므로 **60일 공백은 실질 손해가 아니다.** 오늘 수집을 시작하는 것만이 유일하게 중요하다.

## 11. 리스크

| 리스크 | 대응 |
|---|---|
| **Open API 승인 거부·지연** | 전부가 막힌다. **가장 먼저 신청.** 승인 전에는 스키마·판정 로직·페이지를 목 데이터로 진행 |
| 수수료 10% 요율 변동 | 요율을 코드에 하드코딩하지 않는다. 수익 표시가 필요하면 설정값으로 |
| SEO 단일 채널 의존 | 쿠팡파트너스 사례처럼 알고리즘 한 번에 급감할 수 있다. 앱인토스가 열리면 두 번째 채널로 |
| 토스쇼핑 상품명 검색 수요가 없을 가능성 | **60일이면 실측으로 판별된다.** 초기 투자가 작다는 게 이 안의 진짜 장점 |
| Elastic IP 변경 | 어드민 등록 IP와 불일치하면 즉시 중단 + 알림 (§5 실패 처리) |
| SQLite 파일 손상 | cron 종료 후 일 1회 스냅샷 백업 |

## 12. 안 하는 것

RDS·Redis·회원가입·모바일 앱·크로스 플랫폼 가격 비교(다나와 정면 충돌 + 동일 상품 식별이라는 미해결 난제)·알림 기능(토스 앱이 이미 하고, 어트리뷰션도 안 붙는다).

**앱인토스 미니앱**은 지금 못 한다 — 미니앱에서 쉐어링크를 열면 앱 복귀가 불안정하다(토스 "개선 논의 중"). 고쳐지면 재검토한다.

## 13. 선행 과제

1. **쉐어링크 Open API 신청** — 어드민에서 Access·Secret Key 발급 + 출발지 IP 등록 *(사용자 진행)*
2. **EC2 t4g.small + Elastic IP** — 발급받은 EIP를 어드민에 등록
3. **도메인** — "토스" 사용 불가
