## 0. 공통 전제 — 토스 쉐어링크 사실관계 (2026-08-25 확인)

어떤 아이디어를 고르든 공통으로 깔리는 제약이다. 출처는 [쉐어링크 공식 문서](https://sharelink-docs.toss.im/).

### 수익 구조

| 항목 | 내용 |
|---|---|
| 수수료 | 결제액의 **10%** (이벤트 요율 — 종료 시점 명시돼 있어 **변동 전제로 설계**) |
| 어트리뷰션 | 클릭 후 **24시간**, **공유한 상품이 아닌 다른 상품을 사도 인정**, 24시간 내 여러 건이면 **각 건이 각각 인정** |
| 불인정 | 본인 계정 구매, 가족·지인 교차결제(자전거래), 취소·환불 건 |
| 정산 | 월 1일~말일 발생분 → 익월 25일 지급, 최소 10원 |

> **가장 큰 지렛대**: 어트리뷰션이 24시간 × 전 카테고리라 **추천한 상품을 안 사도 수익이 난다.**
> 즉 "판매"가 아니라 **"클릭 유발"** 이 비즈니스 모델이다. 상품 매칭이 부정확해도 수익이 상쇄된다.

### Open API

- 인증: OAuth2 `client_credentials` → `POST https://oauth2.cert.toss.im/token`, 토큰 유효기간 약 1년
- 베이스: `https://sharelink.toss.im/openapi`
- 스코프: `sharelink:read`(조회) / `sharelink:write`(링크 발급)
- **제공 API 6종이 전부**: 카테고리 트리 / 카테고리 베스트 / 전체 베스트 / 하루특가 / 상품 상세 / 링크 발급
- ⚠️ **키워드 검색 API가 없다.** 진입점이 랭킹·특가·카테고리뿐 → 롱테일 상품을 특정할 수 없다
- 한도: 10 rps · 조회 10,000상품/일 · 링크발급 10,000건/일 (자정 KST 리셋, 서로 독립)
- 링크 발급은 **같은 `tacaItemId`+`publisherId`면 기존 링크 반환** (한도 재차감 없음) → 캐싱하면 사실상 무제한 재사용
- 상품 필드: `displayName` `thumbnailUrl` `displayPrice` `originalPrice` `discountRate` `isSoldOut` `reviewScore` `reviewCount` `rank` (하루특가는 `endAt` 추가)
- ⚠️ 조회 API의 `productUrl`은 **추적 안 됨.** 반드시 링크 발급 API의 `shortUrl`/`originUrl`을 써야 수익이 잡힌다

### 운영상 지켜야 할 것

- **서비스명·도메인에 "토스"를 쓸 수 없다** — 정책상 "검색광고, 도메인 이름 등 토스 키워드 활용 금지" + 토스 사칭·공식 오인 금지
- **대가성 문구 필수 표시** — 모든 노출 지점에. 권장 문구: *"이 콘텐츠는 토스쇼핑 쉐어링크 활동의 일환으로, 링크를 통한 구매가 발생하면 일정 수수료를 지급받습니다."*
- **미동의 개인 메신저·SMS 광고 금지** → 유저가 직접 구독한 채널만 안전
- **출발지 IP 화이트리스트 필수** → Vercel·Lambda 기본 구성으로는 호출 불가. 고정 IP 필요
- API 인증정보는 **사업자(정산 거래처) 단위로 1개**

### 토스쇼핑 자체 성격

- 오픈마켓(2023-09 전환). **패션·생활용품·소액 단품**이 강세, 생필품·식품 반응이 빠름
- 특가·행사 상품은 셀러 판매수수료 0% → 특가 물량이 계속 나옴
- ⚠️ 고가·브랜드 충성 강한 품목(캠핑 장비, 고급 운동머신)은 약함

### 시장 규모 (2026-08-25 확인) — 상한은 문제가 아니다

- **토스쇼핑 MAU 약 900만명** (토스 앱 전체 2,480만 MAU의 1/3 이상)
- **거래액(GMV) 전년 대비 약 +80%**, 운영 셀러 수 2배 이상
- 토스 유저는 결제수단이 이미 등록돼 있어 **구매 마찰이 거의 0** → 쿠팡파트너스보다 전환에 유리한 조건
- 수수료 10%는 쿠팡파트너스(3~5%)의 2~3배

### 앱인토스(미니앱) — **실행 환경으로 확정** (2026-08-25)

웹사이트 채널은 버렸다. 미니앱은 **검색엔진에 색인되지 않으므로 SEO 전략이 통째로 무효**이고, 트래픽은 토스 앱 내 노출에서 온다. 대신 SEO 3~6개월 대기가 없다.

- 스택에 선택지가 없다: Vite + React **18** + `@apps-in-toss/web-framework` + `@toss/tds-mobile` (React 19는 TDS peer 제약으로 불가)
- 정적 SPA 번들(`.ait`)을 토스 인프라가 호스팅한다. 서버 렌더링이 없어 데이터가 필요하면 별도 API 서버가 든다
- **외부 링크 정책은 유리하다.** 허용 예시에 *"각 제품을 소개·추천한 뒤 최저가 구매 플랫폼으로 이동"* 이 명시돼 있다. 제한되는 건 *"주요 기능·흐름이 외부 링크에 의존하는 구조"*다
- ⚠️ **앱이 1만 개 넘게 있다.** 아이템을 정하기 **전에** 토스 앱에서 검색해 선점 여부를 확인한다(판정 기준 ④)

### 💡 리워드 광고 — 어필리에이트보다 강할 수 있다 (2026-08-25 발견)

「백원마켓」(리뷰 3,730)을 뜯어보고 알게 된 것. **광고를 보고 가격을 깎는** 리워드 커머스 게임인데, 수익 모델이 어필리에이트가 아니라 **광고**다.

- 어필리에이트는 **구매까지 가야** 수익이지만 광고는 **시청만으로** 수익이 난다
- 쉐어링크의 앱 복귀 불안정 문제도 우회한다
- SDK 지원: `loadFullScreenAd` / `showFullScreenAd`(load와 show가 분리) · `TossAds.attachBanner` · `GoogleAdMob.*`
- **load/show 분리가 중요하다** — 미리 불러두고 필요한 순간 노출하면 로딩 대기가 0이 된다

→ 채택 안(④)이 이 발견을 그대로 쓴다.

### ⚠️ 미니앱 + 쉐어링크의 미해결 함정

[앱인토스](https://toss.im/apps-in-toss)는 계약 없이 누구나 낼 수 있고 **3,000만 유저에게 노출**된다. 다만 쉐어링크와 함께 쓸 때 확인된 문제가 있다:

**미니앱에서 토스쇼핑 쉐어링크를 열면 앱 복귀가 불안정하다.** `openURL()`로 열면 세션이 꼬인다. 토스 답변은 *"내부 개선 논의 중"*(미해결)이고, 제보자는 결국 **토스쇼핑 링크를 빼고 쿠팡 링크만 쓰고 있다** ([앱인토스 개발자 커뮤니티](https://techchat-apps-in-toss.toss.im/t/toss-im/4625)).

- 프레임워크에서 `openURL`은 **deprecated**이고 `Device.openURL`이 후속이다. **제보는 구 API 기준**이라 후속에서 고쳐졌을 가능성이 남아 있다 → 둘 다 실측한다
- 검증 도구는 `miniapp/`에 만들어 뒀다. **Open API 승인 없이** 수동 발급 링크로 잴 수 있다
- 채택 안(④)에서는 쉐어링크가 **보조 수익**이라 이게 실패해도 치명적이지 않다. 광고 단독으로 간다

**심사**: "기존 회사·서비스를 단순 홍보하기 위해 미니앱을 출시할 수 없다" + 전수점검 중. 기능이 미니앱 안에서 완결되게 설계하면 문제되지 않는다(외부 링크 정책의 허용 예시에 우리 형태가 명시돼 있다).

### 트래픽 획득 경로 — 이게 아이템 선정의 1순위 기준이다

수익 = 트래픽 × 전환 × 객단가 × 10% 에서 가장 크게 움직이는 건 **트래픽**이다.

| 경로 | 판정 |
|---|---|
| SEO | **사실상 유일한 현실적 경로.** 단 3~6개월 걸리고 알고리즘 리스크가 있다 |
| 앱인토스 미니앱 | 지금은 봉쇄 (위 참조) |
| 커뮤니티·SNS | 정책상 "무분별한 게시" 금지 + 핫딜 커뮤니티는 어필리에이트에 적대적 |
| 유료광고 | 10% 수수료로 CAC 감당 어려움. **토스 키워드 검색광고는 정책상 금지** |

⚠️ **SEO 단일 채널 의존의 실증 위험**: 쿠팡파트너스 사례에서 "블로그 로직 변경으로 매출 급감·저품질" 보고가 반복된다. 알고리즘 한 번에 0이 될 수 있다는 걸 전제로 설계할 것.

### 현재 상태

- 쉐어링크 가입 ✅ / **Open API 미신청** ⬜ ← 선행 과제. 어드민에서 Access·Secret Key + 출발지 IP 등록 필요
- 시범운영 중이라 승인 기간 불확실
- 인프라: **AWS EC2 + Elastic IP** 로 결정 (2026-08-25). 가정용 회선은 유동 IP라 화이트리스트가 조용히 깨진다. EC2가 하는 일은 ⓐ 정적 파일 서빙 ⓑ cron 스크립트 두 가지뿐 — **API 서버·DB는 없다**
  - ⚠️ 2024-02부터 모든 퍼블릭 IPv4에 시간당 과금(~$3.6/월). t4g.nano 인스턴스비와 비슷해 실질 비용이 두 배가 된다

## 1. ✅ 채택 — ④ 보유 기구 기반 홈트 + **휴식 시간 광고**

> **2026-08-25 채택 → 같은 날 경쟁 조사로 접음 → 같은 날 새 각도로 부활.**
> 접었던 이유는 그대로 유효하다(아래 ❌ 절). **부활시킨 것은 수익 모델이지 기능이 아니다.**

### ✅ 부활시킨 것 — 「휴식 시간 = 광고 슬롯」

세트 사이 휴식 타이머 동안 전면 광고를 재생한다. 설계는 [2026-08-25-design.md](2026-08-25-design.md).

**왜 이건 다른가 — 판정 기준 ②를 통과하는 첫 차별점이다**

- 보통 리워드 광고는 "보상을 받으려면 참으세요"라 사용자에게 손해다. **운동 중 휴식은 어차피 기다리는 시간**이라 광고가 마찰을 만들지 않는다
- 한 세션 12세트면 **광고 슬롯 12개**. 보통 앱은 세션당 1~2회가 한계다
- **Fitbod(월 $15.99)·플랜핏은 구독 모델이라 이걸 못 한다.** 구독자에게 운동 중 광고를 12번 트는 건 브랜드 자살이다. 기술이 아니라 **수익 모델이 충돌해서 못 하는 자리**다
- 운동 앱의 고질병인 리텐션(40~50% 3개월 내 이탈)도 덜 아프다 — **구독은 이탈하면 0이지만 광고는 쓰는 동안 뽑는다**
- 앱인토스 검색 결과 **휴식 시간에 광고를 트는 앱은 없었다**(2026-08-25 사용자 확인)

**접었을 때 지적한 구멍도 메워진다**: *"기구를 다 사면 수익이 0이 된다"* → 광고가 바닥을 받친다. 쉐어링크는 기구 해금 자리에 보조 수익으로 남는다.

⚠️ **규율이 곧 수익 구조다.** 광고가 휴식보다 길거나 운동 중에 끼어들면 사용자가 이탈하고, 그러면 12회라는 노출 밀도 자체가 사라진다. 돈이 되는 이유가 "어차피 버리는 시간"이라 그 선을 넘으면 근거가 무너진다.

**한 줄**: 내가 **가진 운동기구를 등록**하면 그것만으로 되는 루틴을 짜주고, 없는 기구는 *"이거 하나 사면 운동이 몇 개 늘어나는지"* 를 숫자로 보여준다.

**처음 채택한 이유**: 만드는 사람이 직접 쓸 서비스다(도그푸딩). 구매 욕구가 서비스의 부산물로 자연 발생한다 — 광고가 아니라 데이터에서 나온 사실을 보여주는 자리에 링크가 붙는다.

### ❌ 처음 접었던 이유 — 코어 메커닉이 이미 점유돼 있다 (여전히 유효)

> 아래는 **기능**으로 승부하려 했을 때의 판정이고, 지금도 맞다. 그래서 이 앱은 "더 나은 루틴 추천"으로 이기려 하지 않는다. 이기는 자리는 **수익 모델**이다.

**[Fitbod](https://en.wikipedia.org/wiki/Fitbod)** (2015 창업) — 다운로드 1,500만+ · 활성 250만+ · 누적 운동기록 1억 5,700만회 · 월 $15.99
> **"장비 기반 맞춤 루틴 생성이 핵심 기능"** — 이 아이디어의 코어 그 자체다. ML 기반 + 근육 회복 추적 + 홈짐/헬스장/여행지 프로필 분리까지 한다.

**[플랜핏](https://www.planfit.ai/ko)** (한국) — 100만+ 유저. 헬스장을 등록하면 **그 헬스장 장비 기준으로 루틴 추천**, 집에서도 동일. **기본 무료**, ChatGPT AI 코치가 프리미엄.

→ 4~6주 들여 만들 MVP가 **플랜핏 무료 티어보다 못하다.**

**시장 포화도**: 모바일 헬스 앱 10만 개+, 피트니스 앱만 수천 개에 매년 수백 개 출시. 시장은 크지만($12B→$38B) 상위 소수가 독식하고 **40~50%가 3개월 내 이탈**한다.

**주장했던 차별점 2개를 냉정하게 재검증하면**

| 차별점 | 판정 |
|---|---|
| "덤벨 사면 +123개" 해금 수치 | 진짜 빈틈은 맞다. Fitbod·플랜핏은 장비를 *제약조건*으로만 쓰고 *성장 축*으로 안 쓴다. **하지만 Fitbod가 하루면 붙일 기능이다. 해자가 아니다** |
| 어필리에이트 연결 | 그들이 못 해서 안 하는 게 아니라 **월 $15.99 구독이 기구 수수료보다 훨씬 크기 때문**이다 |

→ **차별점 두 개 모두 "경쟁사가 안 하는 데에 이유가 있는 것"이었다.** 이 패턴이 보이면 접는 게 맞다.

**되살릴 조건**: 목적이 수익이 아니라 학습·재미·포트폴리오로 바뀌면. 그때는 경쟁 분석이 무의미해진다.

### 그래도 남길 자산 — 아래 실측과 설계는 재사용 가능하다

```
+ 덤벨        234개  (+123, 2.1배)   ← 단일 최대 해금

```

→ 첫 구매 추천은 **덤벨**. 해금량이 압도적이고 토스쇼핑 소액 단품 강세와도 맞는다.

**데이터 소스**: [free-exercise-db](https://github.com/yuhonas/free-exercise-db) — 873개, **Unlicense(퍼블릭 도메인)**, 이미지 포함, 단일 JSON. 영어라 번역 필요.

- 대안 [hasaneyldrm/exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset)은 한국어 instructions가 있지만 **GIF가 © Gym visual** 이라 미디어를 못 쓴다 → 탈락

**알려진 데이터 문제** (정제 필요)

1. `equipment: null` 77개는 대부분 맨몸 스트레칭 → 맨몸에 합치면 111→188개가 되고 덤벨 배수가 2.1→1.24배로 떨어진다. `category`로 근력/스트레칭을 분리해야 훅이 산다
2. `other` 122개가 잡동사니 — Ab Roller(홈트 가능) / Atlas Stones(스트롱맨) / Battling Ropes(짐 전용)가 섞여 수동 재분류 필요
3. 밴드가 20개뿐이라 해금 효과가 초라해 보인다

**아키텍처 결론**: **서버 0대.** 쉐어링크는 유저별로 다를 필요가 없으니 장비별 추천 상품 링크를 미리 발급해 정적 JSON에 박아둔다. 고정 IP는 주 1회 갱신 스크립트 돌릴 때만 필요(집 IP 등록). 정적 사이트 + localStorage로 끝.

**약점**: 운동앱은 레드오션(Nike Training·삼성헬스)이고 리텐션 싸움이다. 구매도 초기 1회에 몰린다.

## 2. 보류 — ① 자취·이사 준비 플래너

**한 줄**: "원룸 이사 D-14"를 입력하면 날짜별 할 일과 **그 시점에 필요한 물건 체크리스트**를 준다.

**왜 좋았나**

- 인생에서 **가장 강한 대량 구매 순간**이고, 사람들이 뭘 사야 할지 진짜 모른다
- 커튼·압축봉·행거·멀티탭·청소용품 — 전부 토스쇼핑 강세 품목(생활용품·소액 단품)과 정확히 일치
- 24시간 안에 여러 개를 사고 **각 구매 건이 각각 인정**된다 → 어트리뷰션 효과 최대
- "자취 필수템", "원룸 이사 준비물" SEO 유입 경로가 명확
- 만드는 난이도가 후보 중 **가장 낮다**

**약점**: 일회성 사용, 리텐션 0.
다만 어필리에이트 모델은 리텐션이 필요 없다 — 한 번 쓰고 나가도 그날 수익이 난다. 신규 유입만 계속 만들면 되는 구조라 이 약점은 생각보다 가볍다.

**왜 지금 안 하나**: 만드는 사람이 직접 쓸 서비스가 아니라서. ④를 먼저 한다.

**되살릴 조건**: ④의 유입이 정체되거나, SEO 기반 유입 실험을 따로 돌려보고 싶을 때. **④와 엔진이 겹치지 않으니 독립 프로젝트로 가는 게 맞다.**

## 3. 검토했으나 접은 안

### ② 육아 월령 준비물 + 소모품 재구매 알림

**수익 잠재력은 후보 중 최대**였다. 출산 준비(대량 구매) → 월령별 소모품(반복 구매)으로 이어져 ①의 리텐션 약점을 구조적으로 해결한다. 알림 명분이 "본인이 등록한 소진 주기"라 미동의 광고 정책에도 걸리지 않는다.

**접은 이유**: 육아용품은 안전·신뢰 민감도가 높아 대충 추천하면 바로 신뢰를 잃는다. 도메인 부담이 크고 만드는 사람의 경험 영역이 아니다.

### ③ 반려동물 케어 캘린더

②와 **완전히 같은 엔진**인데 시장은 작고 경쟁도 적고 신뢰 부담이 낮다. 사료·모래·패드의 소진 주기가 명확해 알림이 자연스럽다.
**접은 이유**: ②의 하위 호환. ②를 할 거면 ②를, 아니면 ④를.

### 커머스 방향 — "이 할인 진짜야?" 할인 검증기

매일 가격을 스냅샷해 시계열을 쌓고 *"할인율 40%라는데 지난 60일 평균가가 오늘보다 쌌다"* 를 판정하는 서비스.

**구조적 장점이 컸다**: 커머스 사업자는 자기 셀러의 할인이 가짜라고 표시할 수 없다 → 토스가 원천적으로 못 만드는 기능 = 영구 해자. 다나와·특가요정·헬로프라이스는 전부 쿠팡 중심이라 토스쇼핑은 무주공산이었다.

**1차 접은 이유**: 시장이 작다(가격 민감층) / 초기 60일은 데이터가 없어 판정 불가 / 커버리지가 베스트·특가로 제한 / 만드는 사람이 쓸 서비스가 아니다.

목적이 "수익"으로 확정되면서 마지막 이유가 사라져 **한 번 채택했다가, 실물 확인 후 최종 기각했다.**

### ❌ 최종 기각 — 전제가 사실과 달랐다 (2026-08-25 실물 확인)

**토스쇼핑 상품 상세에 「최대할인가」 표시와 「가격 비교하기」 버튼이 이미 있다.** 눌러보면 네이버·11번가·쿠팡·G마켓 등 **크로스몰 가격 비교**가 뜨고 해당 몰로 이동까지 된다.

이건 이 안의 핵심 전제를 정면으로 반박한다:

| 주장했던 것 | 사실 |
|---|---|
| "커머스 사업자는 자기 할인이 가짜라고 말 못 한다 → 구조적 해자" | **토스쇼핑은 「최대할인가」라는 판정 문구를 이미 붙이고, 자기 매출을 깎으면서까지 타 몰로 보내준다.** 이 회사는 가격 정직성을 브랜드로 쓰고 있다 |
| "가격 시계열이 해자" | **오늘 시작하면 누구나 60일 뒤 갖는다.** 조회 한도 10,000/일은 모두에게 같아 커버리지 격차도 안 벌어진다 |

남은 자리는 **시간축**뿐이었다 — 크로스몰은 *"다른 가게보다 싼가"*(공간), 이력은 *"평소보다 싼가"*(시간). 크로스몰 비교는 원가 뻥튀기를 못 잡으니 각도 자체는 비어 있었다.
**그러나 해자가 60일뿐인데, 크로스몰 비교까지 넣은 회사라면 이력을 넣을 동기도 능력도 있다.** 플랫폼이 채울 자리에 밖에서 링크로 보내는 쪽이 들어갈 이유가 없다.

**부수 확인**: 앱인토스의 「오늘의 할인」(리뷰 12)은 쉐어링크 어필리에이트 앱이 맞지만 **할인율 나열뿐**이고 이력·판정이 없다. 「백원마켓」(리뷰 3,730)은 **광고 보고 가격을 깎는 리워드 커머스 게임**이라 다른 종류였다.

**되살릴 조건**: 토스쇼핑이 크로스몰 비교를 걷어내거나, 다른 커머스 채널(쉐어링크 외)에서 같은 구조를 하게 될 때.

### 접은 안 — 하루특가 알림 봇

`endAt` 마감 카운트다운을 이용한 조건 알림 봇. **가장 작고 빨랐지만 접었다.**

**접은 이유가 중복이 아니라는 게 중요하다**: 토스쇼핑에 이미 [장바구니 알림 쿠폰](https://shopping-docs.toss.im/shopping-operations/price/undefined)이 있어 겹치기도 하지만, 진짜 이유는 —

> **토스 앱 안에서 일어난 구매는 어트리뷰션이 0이다.**

알림 서비스는 토스와 같은 자리에서 싸우는 건데 그 자리는 토스가 무료로 이기고 나는 수익도 못 받는다. 구조적으로 진다.

(참고로 토스의 알림에는 구멍이 셋 있다 — 셀러가 쿠폰을 걸어야만 오고, 이미 담은 상품에만 오고, 가격이 오르는 건 절대 안 알려준다. 하지만 이 구멍을 메워도 위 문제가 남는다.)

### 접은 안 — 크리에이터용 자동 상품카드 위젯

블로그에 스크립트 한 줄 넣으면 맥락에 맞는 상품 카드가 자동 삽입되고 수익을 분배하는 B2B2C.
**접은 이유**: API 인증정보가 사업자 단위 1개라 남의 수익을 내가 받아 나눠주는 형태가 된다 → 원천징수·세금계산서 문제. 게다가 검색 API가 없어 글 맥락 매칭 품질에 한계가 있다.

### 검토 후 뺀 도메인

- **캠핑·차박 장비 플래너** — 브랜드 충성이 강하고 고가라 토스쇼핑의 소액 단품 강세와 어긋난다
- **요리 레시피 → 장보기** — 신선식품은 마켓컬리·쿠팡프레시가 압도
- **선물 추천** — 사실상 커머스 큐레이션이라 위에서 접은 자리와 같다
- **시험·자격증 플래너 + 문구** — 객단가가 너무 낮아 10%가 몇백 원
- **매일 자동 콘텐츠 발행** — 서비스가 아니라 파밍이고, 정책의 "무분별한 게시" 조항에 걸리기 쉽다

## 4. 아이디어를 고르는 잣대 (다음에 또 고를 때 쓴다)

```
수익 = 클릭유발률 × 24h내 구매확률 × [24h내 총 구매액] × 10%
```

제일 크게 움직이는 건 **총 구매액**이다. 그러니 **한 번에 많이 사는 순간**(이사·출산·홈짐 구축)이나 **반복해서 사는 순간**(육아·반려동물 소모품)에 서 있어야 한다.

### 통과 테스트 4개 — 하나라도 걸리면 접는다

**⓪ 먼저 토스 앱에서 검색해 선점 여부를 확인한다.** ← 가장 비싸게 배운 것

앱인토스에 앱이 1만 개 넘게 있다. 이 프로젝트는 **두 번 다 설계를 끝낸 뒤에 경쟁자를 발견했다**(홈트→Fitbod·플랜핏, 할인 검증기→토스쇼핑 자체 기능). 순서를 뒤집는다: **선점 확인 → 설계**.

- 있어도 바로 접지 않는다. 「오늘의 할인」처럼 *같은 재료를 쓰지만 다른 질문에 답하는* 경우가 있다
- 볼 것은 **우리 차별점 그 자체를 하는가**이지 "비슷한 앱이 있는가"가 아니다
- 플랫폼(토스쇼핑·토스 본체)이 이미 하는지도 함께 본다. **플랫폼이 그 자리에 있으면 못 이긴다**

**① 구매 욕구가 서비스의 *부산물로 자연 발생하는가.***
억지로 붙인 배너면 실패다. **"이거 없으면 다음 단계를 못 하네"** 가 돼야 한다.

**② 내 차별점을, 경쟁사가 *안 하는 데에 이유가 있지는 않은가.*** ← ④에서 배운 것
차별점을 찾았으면 반드시 되물어야 한다. *"덩치 큰 경쟁사가 이걸 왜 안 할까?"*
- **하루면 붙일 수 있는 기능**이면 해자가 아니다 (④의 "해금 수치")
- **더 나은 수익모델이 있어서 안 하는 것**이면 나도 그 모델을 못 이긴다 (④의 어필리에이트 vs 월 $15.99 구독)
- 진짜 해자는 **경쟁사가 구조적으로 못 하는 것**이다 (커머스 사업자는 자기 할인이 가짜라고 말할 수 없다)

**③ 트래픽을 어디서 가져올지 *먼저* 답할 수 있는가.** ← 목적이 수익일 때 1순위
아이템의 우아함보다 유입 경로가 먼저다. 위 「트래픽 획득 경로」 표 참조.
**콘텐츠 생산 비용이 0인가**도 여기서 갈린다 — 1인 개발이면 cron이 콘텐츠를 쌓는 안이 손으로 쓰는 안을 이긴다.

**그리고 트레이드오프를 잊지 말 것**

| | 커머스 방향(할인 검증기) | 도메인 서비스 방향(④·①) |
|---|---|---|
| 해자 | 강함 — 데이터가 곧 제품 | **서비스 품질에 달림** |
| 시장 | 작음(가격 민감층) | 큼 |
| 쉐어링크의 역할 | 제품 그 자체 | **수익화 수단일 뿐** |

도메인 서비스 방향은 **서비스가 재미없으면 유저 0 → 수익 0**이다. 쉐어링크가 차별점이 되어주지 않는다.
