# 기록 화면 캘린더 개편 — 설계 (2026-08-28)

> 요구는 두 문장이다: **"기록 화면을 월간 캘린더로 바꾼다. 날짜를 터치하면 그날 찍은
> 눈바디와 그날 한 운동을 플로팅 카드로 보여준다."** 눈바디 촬영 입구는 루틴 완료
> 화면으로 일원화한다(운동한 날만 찍을 수 있게 — 사용자 결정 2026-08-28).
>
> 시안 비교(A 주간 스트립 하이브리드 / B 월간 캘린더 / C 타임라인 리스트)에서 **B로
> 확정**됐다. 리서치 근거: Hevy(캘린더 + 운동일 하이라이트 + 날짜 탭 → 상세),
> 플랜핏·번핏(월간 운동 달력), Strong(목록은 요약만·상세는 한 겹 아래).

## 0. 요약

**기록 화면의 주인이 리스트 → 월간 캘린더로 바뀐다.** 내용 조회는 날짜 터치 시 뜨는
플로팅 카드(딤 + 바텀시트)가 담당한다. 1 PR로 나간다 — 새 순수 로직은
`logic/calendar.ts` 하나, 화면은 `History.tsx` 개편이 전부다. 저장 형식·데이터는
한 줄도 안 바뀐다(읽기 전용 개편).

이미 합의된 결정:

| # | 결정 | 내용 |
|---|---|---|
| 1 | **캘린더가 주인** | 기존 카드 리스트 제거. 내용은 플로팅 카드가 담당 |
| 2 | **마커 2종** | 파란 점 = 운동한 날, 초록 점 = 눈바디 찍은 날. 오늘 = 파란 테두리. 범례 1줄 |

| 7 | **월 요약 1줄** | 「8월 · 12일 운동 · 눈바디 4장」 — 세는 단위는 **날**(달력과 같은 근거) |

## 1. 목표 / 비목표 (YAGNI)

**목표 (v1)**

- 월간 캘린더: 일요일 시작 7열, 운동/눈바디 마커, 오늘 표시, ‹ › 월 이동, 월 요약
- 플로팅 카드: 그날의 눈바디 사진 + 운동 전체(부위·운동명·세트). 딤 탭·✕로 닫기
- 눈바디 입구 정리: 「오늘 찍기」 제거, 비교 로우만 유지
- 기존 보증 유지: 「기록은 이 기기에만 저장됩니다」 고지, `DEV_TOOLS` 온보딩 다시 보기

**비목표 (⏸ — 지금 안 하는 이유를 함께 적는다)**

- ⏸ **스트릭·주간 요약**(A안 요소) — B 확정으로 접었다. 재방문 장치가 필요해지면
  캘린더 위에 한 줄로 얹을 수 있다(자리는 남는다)
- ⏸ **체감(feel) 표시** — 요구에 없다. 카드 헤더에 이모지 하나 얹는 자리라 필요해지면 그때
- ⏸ **스와이프 제스처**(카드 내려닫기·월 넘기기) — 딤 탭·화살표로 동작은 성립한다.
  웹뷰 터치 제스처는 확대 방지(T-240)와 간섭할 수 있어 요구가 생기면 따로 검증
- ⏸ **캘린더에서 과거 기록 추가**(Hevy의 + 버튼) — 이 앱의 기록은 세션 완료가 만든다.
  손 입력 기록은 데이터 신뢰(승급 판정·프리필)를 흔든다
- ⏸ **카드의 사진 탭 → 전체 보기** — 비교 화면이 이미 크게 보여준다

## 2. 현황 실측 (설계가 딛는 사실)

- `History.tsx` — 눈바디 카드(`BodyPhotoCard`) + 역순 카드 리스트. 촬영(`onShootPhoto`)과
  비교(`onComparePhotos`)의 **유일한 입구**가 이 눈바디 카드다
- 완료 화면(`Workout.tsx`)에 「📷 오늘의 눈바디 남기기」 제안이 **이미 있다** — 기록 저장
  후 호출되는 `onBodyPhoto`. 기록 화면 입구를 걷어도 촬영 경로는 여기 남는다
- ⚠️ **구 설계(§3.1 눈바디)의 근거를 하나 뒤집는다** — 「기록 탭 카드는 운동 안 한 날의
  유일한 촬영 입구」였다. 사용자 결정으로 **운동한 날만 찍는 것이 스펙**이 됐으므로 그
  근거는 폐기한다. 비교로 가는 문이라는 근거는 살아 있어 비교 로우로 축소 유지한다
- `WorkoutRecord.date`·`BodyPhoto.date` 둘 다 `YYYY-MM-DD`(`todayKey`, Asia/Seoul) —
  달력 셀과 문자열 그대로 대조하면 된다. 시간대 계산을 새로 하지 않는다
- 같은 날 레코드가 여러 개일 수 있다(`appendRecord`는 날짜로 합치지 않는다) — 카드는
  그날 레코드를 **전부** 보여준다
- 사진 목록은 `usePhotos`(IndexedDB) — ⚠️ jsdom + fake-indexeddb는 Blob 정체를 잃는다
  (T-232). 화면 테스트는 기존 `History.test.tsx`처럼 `listPhotos`를 목으로 둔다

## 3. 화면

### 3.1 캘린더 (기본 상태)

```
기록
┌──────────────────────────┐
│    ‹  2026년 8월  ›       │
│  일 월 화 수 목 금 토      │
│         · = 마커          │
│  … 26(선택) … 28(오늘) …  │
│   ● 운동  ● 눈바디  ← 범례 │
└──────────────────────────┘
8월 · 12일 운동 · 눈바디 4장   ← 월 요약
┌──────────────────────────┐
│ [썸네일] 눈바디 12장 · 최근 8/26   [비교] │  ← 사진 0장이면 로우 숨김
└──────────────────────────┘
(기록은 이 기기에만… 고지 · DEV_TOOLS 버튼)
```

- 요일 헤더는 **일요일 시작**(국내 달력 관례). 마커는 날짜 아래 점 — 파랑(`--blue`) =
  그날 `WorkoutRecord` 존재, 초록(`--green`, 신설) = 그날 `BodyPhoto` 존재
- 색 둘에만 기대지 않는다 — 범례 1줄 + 카드 내용이 구분을 다시 말한다(마커는 항상
  「운동 왼쪽 · 눈바디 오른쪽」 순서 고정)
- 오늘 = `todayKey()`와 일치하는 셀에 파란 테두리
- 기록·사진이 있는 날만 `<button>`으로 활성화한다. 빈 날은 버튼이 아니다 —
  눌러도 아무 일 없는 버튼을 만드는 대신 처음부터 누를 수 없게

### 3.2 플로팅 카드

- 활성 날짜 터치 → 딤(반투명 검정) + 화면 하단 바텀시트. 구성:
  - 헤더: 「8월 26일 수요일」 + 부위 칩(레코드마다 하나) + ✕
  - 눈바디 사진(있으면): 가로 꽉 찬 썸네일(`useObjectUrl`)
  - 레코드마다: 운동별 줄(이름 + `20×10 · 20×10` — **기존 리스트의 표기 그대로**)
  - 운동 없이 사진만 있는 날(과거 데이터)은 사진만 뜬다
- 닫기: 딤 터치 또는 ✕. 열려 있는 동안 탭바는 그대로 둔다(탭 이동 = 닫기와 같다)
- 시트는 `position: fixed` 오버레이 — 탭바(`--tab-lift`) 위에 얹히는 게 아니라 화면
  밑변부터 덮는다

### 3.3 눈바디 입구 정리

- `BodyPhotoCard` 삭제 → 비교 로우로 교체(최신 썸네일 + 「눈바디 N장 · 최근 M/D」 +
  「비교」 버튼). 사진 0장이면 로우 자체가 없다 — 빈 화면으로 보내는 버튼을 만들지 않는다
- `History`의 `onShootPhoto` prop 제거, `App.tsx` 배선 정리 — 촬영 진입은 완료 화면
  `onBodyPhoto` 하나가 된다. ⚠️ `App.test.tsx`의 진입 배선 테스트를 함께 갱신한다
  (배선은 타입이 못 잡는다 — 눈바디 PR C에서 실측된 함정)

## 4. 로직

### 4.1 `logic/calendar.ts` (신설 — 순수 함수, 라이브러리 0)

```ts
type Ym = { year: number; month: number };            // month 1~12
function monthOf(dateKey: string): Ym;                 // 'YYYY-MM-DD' → 그 달
function addMonth(ym: Ym, delta: 1 | -1): Ym;          // 12월↔1월 경계 처리
function monthCells(ym: Ym): (string | null)[];        // 앞 빈칸 null + 'YYYY-MM-DD'…
function formatYm(ym: Ym): string;                     // '2026년 8월'
```

- `monthCells`는 일요일 시작 기준 앞 빈칸(`null`)을 채우고 말일까지 키 문자열을 낸다.
  날짜 키가 전부 `YYYY-MM-DD` 문자열이라 **셀 ↔ 기록 ↔ 사진 대조가 문자열 비교 하나**다
- ⚠️ 셀 생성에 `Date` UTC 메서드를 쓰든 로컬 메서드를 쓰든 **한쪽으로 통일**한다 —
  섞으면 월 경계에서 하루가 밀린다. `todayKey`와의 정합은 「오늘 셀 존재」 테스트로 잠근다

### 4.2 화면 상태 (`History.tsx`)

- `ym`(보는 달, 초기값 = `monthOf(todayKey())`) · `selected`(플로팅 카드의 날짜 키,
  `null`이면 닫힘) — 상태 둘이 전부다
- `useMemo`: `history` → `Map<date, WorkoutRecord[]>`, `photos` → `Map<date, BodyPhoto>`
- 월 요약: 그 달 셀 중 기록 있는 날 수 + 사진 있는 날 수
