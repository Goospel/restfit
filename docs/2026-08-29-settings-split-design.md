# 설정 입구 개편 — 「근육 키우기」 칩 분해 (2026-08-29)

> 시안 2종 비교(자리마다 입구 / 설정 허브)에서 **A안 자리마다 입구로 확정** — 사용자 결정 2026-08-29.
> 페이지 이름도 같은 결정에서 「운동 목적」으로 확정(경험·불편 부위 포함).
> 시안: https://claude.ai/code/artifact/33954386-c831-4438-b5ec-ceb4d0730cc8

## 1. 배경 · 문제

홈 오른쪽 위의 칩은 라벨이 **현재 목적 이름 그대로**(예: 「근육 키우기」)인데, 누르면
`Settings.tsx` 한 페이지가 열리고 그 안에 **보유 기구 / 운동 목적 / 운동 경험 / 불편한 부위**
4종 설정이 다 들어 있다. 라벨이 내용의 4분의 1만 말한다 — 기구를 바꾸러 「근육 키우기」를
누를 사람은 없다(사용자 진단).

구 설계(`Settings.tsx` 주석)는 「기구와 목적은 둘 다 내 조건이라 성격이 같다」로 한 페이지를
정당화했는데, **입구 라벨이 목적 이름인 순간 그 묶음은 못 찾는 묶음이 된다.** 이 근거는
이 개편으로 폐기한다.

## 2. 확정 결정

| # | 결정 | 내용 |
|---|---|---|
| 1 | 입구 방식 | **A안 — 허브 없이, 입구를 그 설정이 생각나는 자리에.** B안(⚙ 설정 → 두 줄 허브) 기각: 화면 하나 값을 못 하는 허브가 생기고, 기구가 다시 「설정 뒤에 숨는」 지금 문제의 약화판이 된다 |
| 2 | 홈 칩 | 라벨 **「목적 · {현재 목적} ›」** — 여는 곳도 운동 목적 페이지뿐. 접두어가 버튼의 정체를, 현재 값이 상태를, ›가 눌림을 말한다 |
| 3 | 기구 입구 | **기구 탭 맨 위 요약 카드** 「내 보유 기구 N개 + 바꾸기」 — 기구를 바꿔야겠다는 생각이 드는 화면이 기구 탭이고, 추천의 기준(내 보유 기구)도 함께 드러난다 |
| 4 | 페이지 분할 | `Settings.tsx` → **「보유 기구」 · 「운동 목적」 2페이지**로 분해하고 삭제 |
| 5 | 경험·부위 배치 | **운동 목적 페이지에 함께**(사용자 결정). 목적(횟수·휴식)·경험(난이도)·부위(제외) 셋 다 루틴을 몸에 맞추는 같은 축. 페이지명은 온보딩 어휘 그대로 「운동 목적」 |
| 6 | 빈 루틴 화면 | 「설정 열기」 1버튼 → **「보유 기구 확인」·「불편한 부위 확인」 2버튼** — 갈 곳이 둘로 나뉘었으니 버튼도 나뉜다 |
| 7 | 탭바 | **불변.** 2회 반려된 표면(T-222·T-224)이라 이 개편은 탭바에 손대지 않는다 |

## 3. 화면 설계

### 3.1 홈 (`Home.tsx`)

- **목적 칩**: 텍스트 `목적 · ${GOALS[goal].label} ›`. 아이콘은 뺀다 — 접두어가 정체를
  말하므로 아이콘까지 있으면 칩이 두 줄로 밀릴 만큼 길어진다. 스타일(파랑 틴트)은 유지.
  onClick → **운동 목적 페이지**. 「왜 6~12회·150초인지」를 설명하는 역할(기존 주석)은 그대로다.
- **개인화 유도 칩**(`!profile && history.length > 0`): 문구 그대로, 목적지만
  **운동 목적 페이지**로 — 경험이 그 페이지에 있다.
- **빈 루틴 화면**: 안내 문구 유지. `ui.secondary` 버튼 두 개를 세로로 —
  「보유 기구 확인」 → 보유 기구 페이지 / 「불편한 부위 확인」 → 운동 목적 페이지.
- props: `onOpenSettings` 삭제 → `onOpenEquipment` · `onOpenGoal` 추가.

### 3.2 기구 탭 (`Shop.tsx`)

h1·부제 아래, 추천 목록(또는 빈 상태) **위에** 요약 카드 한 장:

- 왼쪽: 제목 **「내 보유 기구 {n}개」** + 아랫줄에 기구 이름 나열(`EQUIPMENT_KO`, ` · ` 구분,
  **한 줄 말줄임** — 정확한 개수는 제목의 n이 말하므로 이름이 잘려도 정보가 안 사라진다).
- `n === 0`이면 제목 **「내 보유 기구 없음」**, 아랫줄 **「맨몸 운동만으로 루틴을 만들고 있어요」**.
- 오른쪽: **「바꾸기」** 버튼(`ui.chip` 계열) → 보유 기구 페이지.
- 추천이 소진돼 빈 상태(「더 권할 기구가 없습니다」)여도 카드는 뜬다 — 기구를 **줄이는** 정리도
  이 입구로 한다.
- props: `onEditEquipment` 추가.

### 3.3 보유 기구 페이지 (`screens/EquipmentSettings.tsx` 신설)

기존 `Settings.tsx` 상단 절반을 그대로 옮긴다. 새로 그리는 것 없음.

- 헤더 「보유 기구」 + 닫기 / 부제 「집에 있는 것만 고르세요…」(기존 문구)
- 카운터 카드 「지금 할 수 있는 근력 운동 N개」 — `STRENGTH` 필터·`effectiveOwned` 로직 그대로 이동
- `EquipmentPicker` + 맨몸 안내 문구(기존)
- props: `owned` · `spec` · `onChange` · `onSpecChange` · `onBack`

### 3.4 운동 목적 페이지 (`screens/GoalSettings.tsx` 신설)

기존 `Settings.tsx` 하단 절반을 그대로 옮긴다. 닫기 버튼이 이 페이지 헤더에도 붙는 것만 다르다.

- 헤더 「운동 목적」 + 닫기 / 부제 「바꾸면 오늘의 루틴에 바로 반영됩니다…」(기존 문구)
- `GoalPicker` → 섹션 「운동 경험」(카드 3 + 기존 주석의 상급 노출 근거 유지) → 섹션
  「불편한 부위」(프로필 null 잠금 안내 + `AvoidPicker`) — 전부 기존 마크업·문구 그대로
- props: `goal` · `onGoalChange` · `profile` · `onProfileChange` · `onBack`

### 3.5 라우팅 (`App.tsx`)

- `settings: boolean` → **`config: 'equipment' | 'goal' | null`** — `photoView`와 같은 패턴.
  값 하나가 「어느 페이지냐 아니냐」를 다 말해서 두 페이지가 동시에 켜질 상태가 없다.
- 닫기 → `null` → **보던 탭으로 복귀**(tab 상태가 보존되므로 자동): 홈에서 열면 홈으로,
  기구 탭에서 열면 기구 탭으로.
- 화면 우선순위는 기존 순서 유지: 온보딩 > 눈바디 > config > 세션 > 탭.
