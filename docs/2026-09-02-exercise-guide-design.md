# 운동 설명 「동작 보기」 — 세트 화면 바텀시트 (2026-09-02)

> 시안 3×3(설명 방식 ㄱ/ㄴ/ㄷ × 디자인 A/B/C) 비교에서 **A안 + ㄷ, 버튼명 「동작 보기」로 확정** — 사용자 결정 2026-09-02.
> 시트 안 교차 재생 여부는 답이 없어 시안 그대로 **두 장 나란히**로 간다.
> 시안: https://claude.ai/code/artifact/1b87e610-e76a-42ae-9b3d-78c86ef4b410

## 1. 배경 · 문제

추천 풀이 640개라 **이름만으로 모르는 운동**이 자주 나온다(「조트만 컬」「케틀벨 윈드밀」 — 사용자 제보). 지금 세트 화면(`Workout.tsx`)에는 88px 사진 한 장(시작 자세)과 이름·부위뿐이라, 모르는 운동을 만나면 앱 밖에서 찾아봐야 한다.

다양성을 줄이는 것은 답이 아니다(사용자 진단). **설명을 필요한 사람만 열어 보게** 한다 — 세트 화면에 버튼 하나를 두고, 누르면 동작을 보여 준다.

가진 재료(2026-09-02 실측, free-exercise-db 채택 640개):

| 재료 | 상태 |
|---|---|
| 자세 사진 | **640개 전부 시작·끝 2장**이 CDN에 있고 실기기 표시 확인됨. `images[1]`은 아직 아무 데서도 안 쓴다 |
| 영어 설명문 `instructions` | 평균 4.2단계 · 647자, 총 41만 자. 빌드 때 **일부러 뺐다**(plan.md ⏸ 「화면에 자리가 없다」) — 이 기능으로 자리가 생기니 그 보류를 뒤집는다 |
| 설명이 0단계인 운동 | 5개. 사진은 있다 |

## 3. 화면 설계

### 3.1 세트 화면 — 칩

```
[운동 2/5]                              그만두기
┌────┐  조트만 컬
│사진│  이두
└────┘  (▶ 동작 보기)          ← 신설. 이름·부위 아래, 헤더 안
┌──────────────────────────────┐
│           1 / 3세트          │
│  무게 (kg)        횟수       │
│  [   8   ]      [  12  ]     │
└──────────────────────────────┘
[          세트 완료          ]
        이 운동 건너뛰기
```

- 칩은 `<button>`이다. 접근 이름은 「동작 보기」(아이콘은 `aria-hidden`). `aria-expanded`로 열림 상태를 말한다.
- 헤더가 칩 높이만큼(≈30px) 길어진다. 다른 요소는 한 픽셀도 안 움직인다.

### 3.2 시트

```
━━━━━━━━━━━ dim (탭하면 닫힘) ━━━━━━━━━━━
╭──────────────────────────────╮
│ 조트만 컬                     │  h2
│ 이두 · 덤벨 · 중급             │  MUSCLE_KO · EQUIPMENT_KO · LEVEL_KO
│ ┌────────┐    ┌────────┐     │
│ │  시작   │ →  │   끝   │     │  images[0] / images[1], 정사각형, 폭의 절반씩
│ └────────┘    └────────┘     │
│ ① 덤벨을 양손에 들고 바로 선다… │  2차 PR. 없으면 이 블록이 통째로 없다
│ ② 위팔은 고정한 채…            │
│ [           닫기           ] │  ui.secondary
╰──────────────────────────────╯
```

- `role="dialog"` `aria-modal="true"` `aria-label={운동 이름}`.
- 사진은 `ExerciseImage`를 쓴다. 정사각형이 폭을 따라가야 하므로 `size` 대신 **`fluid`**(width 100% + `aspectRatio: '1'`) 옵션을 하나 더 받는다. 실패 시 대체 표시(이름 첫 글자)는 그대로.
- 라벨 「시작」「끝」은 사진 위 왼쪽 아래 작은 어두운 칩. `images[1]`이 없는 운동이 오면(현재 0개) 한 장만 그린다 — 데이터 방어이지 기능이 아니다.
- 시트 최대 높이는 `ui.sheet`의 `72vh`, 넘치면 시트 안에서 스크롤. 부제의 기구는 `requires`를 `EQUIPMENT_KO`로 옮겨 ` · `로 잇고, 맨몸이면 「맨몸」.

### 3.3 상태

- `guideOpen: boolean` — `Workout` 로컬 state. 세션에 안 넣는다(화면 상태이지 기록이 아니다).
- `current.id`가 바뀌면 `false`로. 휴식 분기·완료 분기는 이 state를 읽지 않는다(세트 진행 분기에서만 렌더).
- 2차: `steps: string[] | null` — 시트가 열릴 때 `loadInstructions(current.id)`를 기다려 채운다. 로딩 중·없음은 둘 다 「목록 없음」으로 그린다(스피너 없음 — 청크 하나라 수십 ms다).

## 4. 데이터 · 로직 (2차 PR)

### 4.1 파일

- `src/data/instructions.json` — `{ "<id>": ["단계1", "단계2", …], … }`. 키는 `exercises.json`의 `id` 부분집합. 0단계 운동 5개는 키 자체가 없다.
- `src/data/instructions.ts` — `export async function loadInstructions(id: string): Promise<string[]>`: `import('./instructions.json')`의 결과에서 `[id] ?? []`. 청크는 한 번 받으면 브라우저가 캐시한다.

### 4.2 번역 규칙 (배치 1회, 결과를 커밋)

원문은 free-exercise-db(Unlicense)의 `instructions`. 번역은 Claude 서브에이전트가 **80개씩 8묶음**으로 나눠 스크래치패드에 `part-N.json`을 쓰고, 합치는 스크립트(`scripts/merge-instructions.mjs`)가 원본 대조 검사를 한 뒤 `instructions.json`을 만든다. 런타임엔 관여하지 않는다(`build-exercises.mjs`와 같은 관계).

문장 규칙:

1. **단계 수 유지.** 원문 n단계 → n단계. 단, 마지막이 「권장 횟수만큼 반복한다」류(*Repeat for the recommended amount of repetitions* 등)면 **그 한 단계만 뺀다** — 횟수는 앱이 정한다.
2. **평서형 「~한다」**, 한 단계 **60자 이하 목표·80자 상한**. 원문의 부연(*This will be your starting position*, *Tip:* …)은 자세·호흡·템포에 관한 것만 남기고 줄인다.
3. 용어는 화면 어휘를 따른다 — 근육은 `MUSCLE_KO`, 기구는 `EQUIPMENT_KO`, 운동명이 나오면 `exercises.json`의 `name`.
4. 영문자를 남기지 않는다. 예외 토큰: `SMR`, `kg`, `cm`.

### 4.3 검사기 (`instructions.test.ts`, 데이터 회귀 가드)

- 모든 키가 `EXERCISES`의 id에 있다.
- 각 값은 길이 ≥ 1의 문자열 배열, 각 문장은 비어 있지 않고 80자 이하.
- `/[A-Za-z]{3,}/`에 걸리는 문장이 없다(예외 토큰 제거 후).
- **키 수 ≥ 600** — 번역이 절반만 들어간 채 머지되는 것을 막는다. 1차 PR에는 이 파일이 없으므로 이 테스트도 2차에 들어간다.

합치는 스크립트의 추가 검사(원본이 있어야 하므로 테스트가 아니라 스크립트에서): 단계 수가 원본과 같거나 정확히 1 적다(규칙 1).

## 5. 테스트 (TDD — 실패를 먼저 본다)

3. 「닫기」를 누르면 dialog가 사라진다. dim(`data-dim`)을 눌러도 사라진다.

## 6. 안 하는 것 (YAGNI)

- **시트 안 교차 재생** — 사용자 미결. 두 장 나란히로 충분하면 안 만든다.
- **휴식 화면에서 다음 운동 미리보기** — 휴식은 광고 자리다(설계 §광고 규율). 지금 필요한 건 세트 화면이다.
- **홈 루틴 목록의 설명 입구** — 같은 시트를 홈에도 달 수 있지만, 「운동 시작 → 횟수 정하는 단계」가 요구였다.
- **본문 스크롤 잠금·슬라이드 애니메이션** — History 시트도 없이 잘 쓰고 있다.
- **ㄴ 요약 한 줄** — 단계가 있으면 요약은 사진이 한다.

## 7. 리스크 · 전제

- ⚠️ **시트가 「세트 완료」를 가린다** — 의도다. 읽고 닫아야 기록한다. 닫는 길이 둘(버튼·dim)이라 막히지 않는다.
- ⚠️ **번역 품질을 사람이 전부 못 읽는다** — 검사기가 형식을 막고, 표본 20개(맨몸 5·덤벨 5·케틀벨 5·스트레칭 5)를 사용자가 읽는 것으로 마감한다. 틀린 단계는 그 키만 고쳐 커밋한다(배치 재실행 없음).
- ⚠️ **청크 크기** — 한글 640×4단계×~45자 ≈ 12만 자, JSON 원문 ≈ 350KB, gzip ≈ 100KB. `.ait` 패키지에 들어가지만 첫 로드 밖이다. 앱인토스 번들 상한은 확인된 수치가 없다 — 2차 PR에서 `ait build` 산출물 크기를 PR body에 적는다.
- `images[1]`이 CDN에서 실패하면 `ExerciseImage`가 첫 글자로 대체한다 — 1차 PR에서 실기기로 두 번째 장이 뜨는지 한 번 본다(`images[0]`과 같은 경로 규칙이라 막힐 이유는 없다).
