# 쉐어링크 작업대

토스쇼핑 링크를 뽑아 [`shareLinks.ts`](../../miniapp/src/data/shareLinks.ts)에 넣는 **노가다용 작업대**.
한 번에 다 못 채우니 **기구마다 파일 하나**로 나눠 뒀다 — 오늘 덤벨만 할 거면 덤벨 파일만 연다.
Open API를 안 쓰는 이유는 [plan.md](../../plan.md) Phase 4.

| 기구 | 작업 파일 | `EquipKey` | 현재 |
|---|---|---|---|
| 덤벨 | [dumbbell.md](dumbbell.md) | `dumbbell` | **1** — 가벼움만 있다 |
| 케틀벨 | [kettlebell.md](kettlebell.md) | `kettlebell` | **24** ✅ 네 구간 다 찼다 |
| 벤치 | [bench.md](bench.md) | `bench` | 0 |
| 밴드 | [band.md](band.md) | `band` | 0 |
| 풀업바 | [pullup-bar.md](pullup-bar.md) | `pullupBar` | 0 |

> **필요한 건 이 5종뿐이다**(`SHOP_CANDIDATES`). 나머지 기구는 링크를 넣어도 추천에 안 떠서 화면에 안 나온다 — 바벨·짐볼·폼롤러·메디신볼·복근롤러는 후보에서 이미 빠졌다(이유는 plan.md Phase 4).

⚠️ **정답은 언제나 [`shareLinks.ts`](../../miniapp/src/data/shareLinks.ts)다.** 기구 파일의 「반영된 링크」는 그 사본이고,
**어긋나면 테스트가 실패한다**(`기구 문서 ↔ shareLinks.ts`) — 한쪽만 고칠 수 없다.
위 표의 **개수만은** 테스트가 안 묶는 눈요약이니, 다르면 파일을 믿는다.

---

## 뽑는 법

1. [`sharelink.toss.im`](https://sharelink.toss.im) → **링크** → **상품 조회**
2. 기구 파일의 **검색어**로 찾는다
3. 상품 카드의 **「링크 발급」** → `https://toss.im/_m/…` 가 나온다
4. 그 파일의 **수집함**에 `상품명 | 링크` 한 줄로 붙인다
5. 코드에 반영되면 수집함에서 지우고 그 파일의 **「반영된 링크」** 표로 옮긴다

> ⚠️ **상품 페이지 주소를 넣으면 수익이 0으로 잡힌다.** 추적이 안 붙기 때문이다.
> 반드시 「링크 발급」이 뱉은 `toss.im/_m/…` 꼴이어야 한다(테스트가 막는다).

> 토스쇼핑 앱의 「쉐어링크 공유하기」도 같은 주소를 주지만 폰을 켜야 한다. 웹이 빠르다.

**한 링크는 기구 파일 안에서 한 자리에만 있다.**

| 자리 | 뜻 |
|---|---|
| **수집함** | 뽑아만 뒀다 — 아직 앱에 안 뜬다 |
| **반영된 링크** | 화면에 뜨고 있다 — `shareLinks.ts`와 **테스트로 묶여 있다** |

옮긴 줄은 수집함에서 지운다. 안 지우면 어느 쪽이 최신인지 알 수 없게 된다.

---

## 한 줄에 뭘 적나 — `weight` · `kg` · `note`

**셋은 하는 일이 다르다.**

| 필드 | 하는 일 | 값 |
|---|---|---|
| `weight` | **필터 축.** 칩이 이걸로 좁힌다 | `light` · `medium` · `heavy` · `adjustable` |
| `kg` | **왼쪽 배지.** 무게순 목록이 눈에 들어오게 한다 | 숫자만 (`4` · `4.5` · `22.6`) |
| `note` | **같은 구간 안에서** 고르는 기준 | 소재·소음·겸용 여부·조절 단수 |

⚠️ **`name`에 kg을 남기지 않는다.** 배지가 말하는 것을 이름이 또 말하면 한 줄에 두 번 뜬다 — 테스트가 막는다.
**조절식만 예외**다. 배지가 「조절식」이라 최대 무게를 이름에서 잃으면 같은 제품군 둘이 구분되지 않는다(`바이줌 조절 케틀벨 13kg` / `22.6kg`).

`note`에 **구간을 또 적지 않는다.** 무게는 배지가, 구간은 칩이 말하므로 필터를 걸면 스무 줄이 전부 같은 말로 시작하게 된다. 그 둘이 못 하는 말만 적는다:

```
소프트 · 바닥 보호   철제   저소음   덤벨 겸용   5단계   그립만 · 원판 별도
```

⚠️ **무게를 모르면 `weight`를 비운다.** 모르는 것에 구간을 붙이면 그게 거짓이다. 비워 두면 칩으로는 못 찾고 「전체」에서만 보인다.

⚠️ **가격은 절대 넣지 않는다.** 정적 파일이라 바뀌어도 못 따라가고, 틀린 가격은 없는 것만 못하다.

---

## 개수보다 「구간을 채웠는가」가 기준이다

**개수 상한을 두지 않는다.** 검색에서 쓸 만한 게 나오면 다 담아도 된다 — 화면에서 **무게 구간 칩**으로 좁히기 때문이다(`productBands`). 처음엔 기구당 3~5개만 두려 했는데, 그러면 고르는 일을 우리가 대신해 버려서 **「내 무게에 맞는 게 없는」 사람**이 생긴다.

대신 볼 것은 **구간이 비지 않았는가**다. 어느 한 구간이 0이면 그 구간을 고른 사람에게는 목록이 없는 것과 같다.

⚠️ **칩은 구간이 둘 이상일 때만 뜬다.** 덤벨은 지금 「가벼움」 하나뿐이라 칩이 없다 — 나머지를 채우면 그때 나타난다.

**구간 경계는 기구마다 다르다**(`WEIGHT_OPTIONS`). 온보딩에서 사용자가 고른 것과 같은 경계라, 여기만 맞추면 사용자가 자기 기구와 바로 대응시킨다. 경계는 각 기구 파일에 적어 뒀다.

## 살아 있는지 점검

> ⚠️ **스크립트로 링크를 두드려 확인하지 않는다.** 운영정책이 *"무효 클릭, 자동 실행, 과도하게 클릭을 유도하는 등 사용자의 의도에 반하는 방식"* 을 금지한다. 추적 링크에 자동 요청을 보내면 클릭으로 집계될 수 있고, 토스 쪽에서는 점검과 어뷰징을 구분할 방법이 없다. **얻는 것보다 잃을 게 크다.**

대신 사람이 확인한다:

1. **실적 대시보드가 1차 신호다.** 클릭은 꾸준한데 전환이 0인 기구가 있으면 그 링크부터 의심한다 — 죽은 링크를 찾으러 다니는 것보다 이쪽이 싸다
2. **어드민 → 링크 → 링크 관리** 에서 발급 목록과 상태를 본다
3. 의심되는 것만 **직접 눌러 본다**(사람의 클릭 1회는 정상 사용이다). 품절·단종이면 같은 검색어로 다시 뽑아 갈아 끼운다
4. 본 날짜와 결과를 그 기구 파일의 **점검 기록**에 한 줄 남긴다 — 언제 봤는지 모르면 매번 처음부터 다시 본다

**주기**: 분기 1회면 충분하다. 상품 단종은 그보다 느리게 일어나고, 급한 신호는 1번이 먼저 알려준다.

⚠️ **앱은 죽은 링크를 못 잡는다.** 목록이 비어 있으면 상품 버튼이 아예 안 뜨지만(`SHARE_LINKS[key] ?? []`), **죽은 링크는 주소가 있으니 버튼도 그대로 뜨고** `Device.openURL`이 브라우저를 열어 404를 보여 준다. 사용자만 헛걸음하고 수익은 조용히 0이 된다 — 그게 주기적으로 보는 이유다.
